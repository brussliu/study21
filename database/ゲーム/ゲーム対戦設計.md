# Study 2.1 ゲーム対戦（五子棋・黑白棋）設計

生徒と保護者が**同時に**対戦する機能の設計。2.0 のゲームは 1 人用だけで対戦のデータが
無いため、これは 2.1 の新規設計（移行するデータは無い）。

- DDL: `database/ゲーム/TBL_GAM_ゲーム対戦.sql`（`GAM_対戦情報` / `GAM_対戦手情報`）
- 画面: `frontend/pc-web/src/views/game/GomokuView.vue` / `ReversiView.vue`（「一人で遊ぶ」/「対戦」）
- ルール: `backend/user-api/.../game/`（サーバー判定）と `frontend/pc-web/src/features/game/gomoku.ts` / `reversi.ts`（1 人用）

## 1. 決めたこと（ユーザーの指定）

| 項目 | 決定 |
|---|---|
| 同時対戦 | **必要**（相手の手がすぐ反映されること） |
| 招待の仕方 | **「2人対戦（ネット対戦）」で【新しい対局】→ 小窓で相手と先手/後手を選んで申し込む**（ユーザー検索はしない） |
| 申し込みの流れ | ② 申し込んでも小窓は閉じない（返事待ちを出す）／③ 相手がオフラインならその旨を出す／④ 相手の画面に応戦ダイアログ／⑤ 応戦しないときは申請側にその旨／⑥ 応戦したら小窓が閉じて対戦開始 |
| 相手がオンラインか | **ゲーム画面を開いている（SSE が繋がっている）こと**で判定する（応戦ダイアログを見られる状態＝申し込める状態） |
| 先手・後手 | **申し込む人が選ぶ**（先手 BLACK / 後手 WHITE）。承諾後の最初の手番は黒を持つ人 |
| 持ち時間 | **制限なし**（放置された対戦は取消できる） |

## 2. 状態の持ち方

1. **`GAM_対戦手情報`（1 手 = 1 行）が盤面の正**。`GAM_対戦情報.盤面` は表示用の写し。
   - 反則（埋まっているマス・他人の手・黑白棋の不正）をサーバーで検証できる
   - 履歴・再生に使える／クライアントの盤面を信用しなくてよい
2. **手番・勝敗・反転・パス・引き分け・投了はサーバーが判定**する。
   1 人用のロジック（`gomoku.ts` / `reversi.ts`）と同じ盤面サイズ・開始配置にする。
3. **`バージョン` で楽観的ロック**。着手は現在の版を送り、合わなければ 409。
4. **DB が唯一の正、SSE は通知だけ**。切断・再読み込みのあとは必ず `GET /matches/{id}` で
   読み直す（通知が落ちても状態は壊れない）。
5. **通知はトランザクションのコミット後に送る**（`GameEventPublisher.publishAfterCommit`）。
   書き込みが確定する前に送ると、通知を受けた画面がすぐ GET しても新しい行が無く、
   申し込みのダイアログが出ない（実機の E2E で見つけた不具合）。

## 3. リアルタイム通知（SSE）

WebSocket ではなく **SSE（Server-Sent Events）** を使う。

| 理由 | 内容 |
|---|---|
| 一方向で足りる | 着手は普通の POST。サーバー → クライアントの通知だけできればよい |
| 依存を増やさない | Spring MVC の `SseEmitter` だけで作れる（`spring-boot-starter-websocket` が不要） |
| 認証 | 既存の Cookie セッションがそのまま使える（`EventSource` は同一オリジンへ Cookie を送る） |

- エンドポイント: `GET /api/user/games/stream`
- イベント: `invited` / `move` / `finished` / `declined` / `cancelled` / `ping`（心拍 25 秒）
- 実装: `accountId → SseEmitter` のメモリ登録（2.1 の user-api は単一インスタンス）。
  **将来 多 インスタンスにするときは PostgreSQL の `LISTEN/NOTIFY`**（同じトランザクションで
  `NOTIFY`）に置き換える。そのとき画面側は変更不要（イベントの形を変えない）。
- nginx（`deploy/docker/nginx.conf` の `/api/user/`）に `proxy_buffering off;` と
  `proxy_read_timeout 1h;` を入れる（SSE がバッファされると届かない）。

## 4. API（`/api/user/games`）

| メソッド | パス | 内容 |
|---|---|---|
| `GET` | `/opponents` | 招待できる相手（自分の子ども／親。親子紐付けで決まる）。`online`（ゲーム画面を開いているか）付き |
| `GET` | `/matches` | 自分の対戦一覧（新しい順） |
| `POST` | `/matches` | 招待（`{ gameType, opponentAccountId, challengerStone }`。`challengerStone` は挑戦者の石＝先手 BLACK / 後手 WHITE。相手がゲーム画面を開いていないと 400） |
| `POST` | `/matches/{id}/accept` / `/decline` | 受ける／断る（相手のみ） |
| `POST` | `/matches/{id}/cancel` | 取消（挑戦者のみ・招待中のみ） |
| `POST` | `/matches/{id}/resign` | 投了（対戦中のみ。勝者＝相手） |
| `GET` | `/matches/{id}` | 盤面・手番・結果・指し手の一覧 |
| `POST` | `/matches/{id}/moves` | 着手（`{ row, col, version }`。検証・判定はサーバー） |
| `GET` | `/stream` | SSE（上記イベント） |

- 権限: **自分の対戦だけ**見える（挑戦者 or 相手）。他人の対戦は 404。
- 着手できないとき（手番でない・埋まっている・ルール違反・版違い）は 400 / 409 で、
  画面はメッセージを出して読み直す。

## 5. ルールの判定（サーバー）

| | 五子棋（GOMOKU） | 黑白棋（REVERSI） |
|---|---|---|
| 盤面 | 15×15（1 人用と同じ） | 8×8（1 人用と同じ） |
| 石 | 黒＝先手（申し込むときに選ぶ） | 黒＝先手（申し込むときに選ぶ） |
| 着手 | 空きマスならどこでも | **返せる石がある場所だけ** |
| 勝敗 | 縦横斜めに 5 連 | 両者置けなくなった時点で石数の多い方（同数は引き分け） |
| パス | なし | 置ける場所が無ければ**自動でパス**（`パスフラグ='1'` の行を入れる） |
| 投了 | `resign` で相手の勝ち | 同左 |
