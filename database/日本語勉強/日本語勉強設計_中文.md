## 2. 术语表（中文 ↔ 日文 ↔ 说明）

同一概念在库、代码、画面里只有一个词。新增字段前先查这张表。

| 中文 | 库里/画面上的日文 | 说明 |
|---|---|---|
| 单词、词条 | 単語 / 見出し語 | 主表一条 = 一个词条。`見出し語` 是表记（写法） |
| 读音 | 読み | 假名读音。**登录时可不填**，由 AI 详细取得回填 |
| 检索键 | 見出し語キー / 読みキー | 应用侧归一化（NFKC・空白）后的键；读音未取得时 `読みキー` 为 `''` |
| 教材、单词书 | 書籍 | 主数据表 `JPN_書籍情報` |
| 单元、课次 | 分類 | `Unit001` 形式。**注意它不是「分类」语义**，是教材的课次/单元 |
| 单元内顺序 | 単語SEQ | 同一教材同一单元内的位置（1 起） |
| 收录 | 収録 | 「这个词收在哪本书的哪个单元第几位」 |
| 详情 | 詳細 | 词条详情。现在是**版本头 ＋ 11 张段落子表**，读取时组装成 1 个 detail 对象 |
| 版本、版 | 版 | 1 行 `JPN_単語詳細情報` ＝ 该词的 1 个完整快照（整词，不是段落级） |
| 生效版、当前版 | 有効版 | `状態コード='ACTIVE'` 的那一版。部分唯一索引保证每词只有 1 版 |
| 历史版 | 履歴 / `ARCHIVED` | 被新版本顶下来的旧版。不删除，可一键切回 |
| 段落 | 段落 | 详情里会增删改的 11 类内容（语义词・例句・文型・会话・会话行・类义语・注意・搭配・关联词・使用场面・练习） |
| 人工行 | 手修正 / `登録元コード='APP'` | 人在画面上改过或新增的行。AI 重取时会被**复制进新版**，不被覆盖 |
| 题目 | 問題 | AI 生成的题目，`問題種別` 有 C1/C2/D/E 四种 |
| 选项、选项池 | 選択肢 / 選択肢プール | 每题 **5〜7 件**（正解 1 ＋ 误答 4〜6）。**不是「4 択的答案」** |
| 提示的选项 | 出題選択肢 | 作成测试时从池里抽出的 4 件（正解 1 ＋ 误答 3，已打乱），固定在 `出題選択肢JSON` |
| 测试 | テスト | 一次测试，`テスト種別` = A〜E |
| 出题 | 出題 | 测试中的一道题（对应一个词）。1 个词 = 1 条出题 |
| 课题 | 課題 | 2.0 的「一道题」概念。**2.1 不建表**，但 `学習日次情報` 沿用了「課題」列名 |
| 技能 | 技能 / 技能区分 | 题型拆分的技能，如 `C_READING_RECOGNITION` |
| 掌握度 | 習得度 / 総合習得度 | 0〜100。技能级 vs 词级 |
| 学习状况 | 学習状況 | 按「用户 × 词」的聚合状态 |
| 日次 | 学習日次 | 按「用户 × 日期」的聚合 |
| AI 生成记录 | AI生成履歴 | 每个「词 × 内容种别」的执行记录 |
| 语音缓存 | 音声キャッシュ | 键 = 文本＋话者＋速度 的 SHA-256 |

## 4. 关系总览

完整 ER 图见 `日本語勉強ER図_中文.md`。核心骨架：

```
ACC_アカウント
   └─(利用者/登録者/更新者)─┬─ JPN_テスト情報 ─1:N─ JPN_テスト出題情報 ─N:1─ JPN_単語情報
                            ├─ JPN_学習状況情報 ─N:1─ JPN_単語情報
                            ├─ JPN_技能習得情報 ─N:1─ JPN_単語情報
                            ├─ JPN_学習日次情報
                            └─ JPN_音声キャッシュ情報

JPN_単語情報 ─1:N─ JPN_単語詳細情報 ─1:N─ 11 张段落子表（CASCADE・每段一张）
                            （版本头。每词只有 1 版 `状態コード='ACTIVE'`）
             ─1:N─ JPN_単語収録情報 ─N:1─ JPN_書籍情報
             ─1:N─ JPN_単語問題情報 ─1:N─ JPN_単語問題選択肢情報（选项池。1 题 5〜7 件）
             ─1:N─ JPN_AI生成履歴情報 ─(无外键)─ BAT_AI呼出履歴情報
```

**详情的版本骨架（重要）**：

```
JPN_単語情報 (1)
   └─ JPN_単語詳細情報 (N)   ← 版本头。1 行 = 该词的 1 个「版」
        ├─ 状態コード='ACTIVE' 的 1 行 = 生效版（部分唯一索引 uq_jpn_detail_active 保证唯一）
        └─ 11 张子表 (N)     ← 行内容。版本被归档时整版一起变历史
```

**「提示的选项」的骨架（重要）**：

```
JPN_単語問題情報 ─1:N─ JPN_単語問題選択肢情報   ← 选项池（正解 1 ＋ 誤答 4〜6）
JPN_テスト情報 ─1:N─ JPN_テスト出題情報          ← 作成测试时抽出的 4 件固定进 出題選択肢JSON
```

**设计取向（重要）**：

- **词是中心**。几乎所有业务表都以 `単語ID` 为轴，学习数据（状况/技能/出题）删除词时会 CASCADE 消失。
- **AI 产物与业务数据分离**：详情与题目是「参考信息」，可重新生成；归档而不删除，因为测试出题可能引用。
- **详情的版本是「整词快照」**：每次取得或人工编辑都新建一版（含全部段落），新建版立刻生效，旧版变 `ARCHIVED`。
  因此任何一版都能完整重现，也能一键切回；人工行在 AI 重取时被复制进新版，不会被覆盖（见 5.4）。
- **「提示的选项」在作成测试时固定**：选项池（5〜7 件）只是素材，真正给学习者的 4 件写在 `出題選択肢JSON`，
  所以同一个测试每次打开选项相同，池被重新生成也不影响已考过的记录（见 5.6・5.8）。
- **聚合表按粒度分开**：词级（`学習状況情報`）、技能级（`技能習得情報`）、日级（`学習日次情報`）各一张，互相之间靠应用重算保持一致。

### 5.4 `JPN_単語詳細情報`　详情版本头（1 词 N 版）

**用途**：**1 行 = 该词的 1 个「版」**（整词快照）。词级内容（核心意味・说明・品词・级别・活用型・自他・重要度・记忆提示）与
小结构（发音・活用形・自他対応的 JSONB）留在这一行，会增删改的段落交给 11 张子表（5.4.1〜5.4.11）。

**版本模型（从 DDL 与代码读出的事实）**

| 事实 | 依据 |
|---|---|
| 「版本的最小单位 = 整词快照」。每次 AI 取得或人工编辑都产生一个完整的新版 | `JapaneseWordAiDetailWriter.createVersion` / `JapaneseServiceImpl.saveWordEditor` 都 INSERT 一整行版本头 ＋ 全部子表行 |
| 1 词 N 版；**部分唯一索引保证 1 词只有 1 版 `ACTIVE`** | `CREATE UNIQUE INDEX uq_jpn_detail_active ON (単語ID) WHERE 状態コード='ACTIVE'` |
| 新建版立刻 `ACTIVE`，原生效版变 `ARCHIVED`（**先归档、后插入**，一条事务） | 部分唯一索引要求顺序如此（`archiveActiveDetail` → `insertDetailVersion`） |
| 「指定哪一版生效」不新建版，只把 `ACTIVE` 移过去 | `PUT /words/{wordId}/detail-versions/{detailId}/active`（`activateDetailVersion`） |
| 未指定时＝最后新建的那版生效（不需要代码） | 因为所有写入路径都以 `ACTIVE` 出生 |
| 人工版也建版，所以误编辑可回退 | 人工版 `生成ID`=NULL・`登録元コード`='APP'・`手修正フラグ`=true |
| 历史版**无限保留**（清理策略留到将来，见第 11 章） | 没有删除版本的代码路径 |

| 列 | 类型 | 空 | 默认 | 说明 |
|---|---|---|---|---|
| `詳細ID` | bigint | NOT NULL | sequence | 主键（沿用旧列名） |
| `単語ID` | bigint | NOT NULL | — | FK → `JPN_単語情報`（CASCADE） |
| `内容版数` | integer | NOT NULL | 1 | 该词内的版本序号（1 起，递增）。`UNIQUE (単語ID, 内容版数)` |
| `状態コード` | varchar(20) | NOT NULL | `'ACTIVE'` | `ACTIVE` 生效 / `ARCHIVED` 历史 |
| `元詳細ID` | bigint | NULL | — | 基于哪一版产生（初版为 NULL）。**无 FK**（自表引用，注释说明） |
| `生成ID` | bigint | NULL | — | `JPN_AI生成履歴情報.生成ID`。人工编辑版为 NULL。**无 FK** |
| `AIプロバイダ` / `AIモデル` | varchar(40) / varchar(120) | NULL | — | 产生这一版的 AI（人工版从来源版继承） |
| `取得日時` | timestamp | NULL | — | 产生这一版的时间（人工版也写当前时刻） |
| `手修正フラグ` | boolean | NOT NULL | false | 这一版是否含人工编辑 |
| `備考` | text | NULL | — | 切换生效版时的理由等 |
| `核心意味` / `説明_日本語` / `説明_中国語` | text | NULL | — | 词级内容 |
| `品詞` / `JLPTレベル` / `活用型` / `自他` | varchar(100) / varchar(10) / varchar(100) / varchar(20) | NULL | — | `JLPTレベル` 只允许 `N1`〜`N5`；`自他` 只允许 `TRANSITIVE`/`INTRANSITIVE`/`BOTH`/`NONE` |
| `重要度` | smallint | NULL | — | 1〜5 |
| `記憶ヒント` / `記憶ヒント根拠` | text | NULL | — | 两者都空时组装结果里 `memoryHint` 为 null |
| `発音JSON` | jsonb | NOT NULL | `'{}'` | 单数对象：`reading`/`accentType`/`accentNotation`/`hint`/`hasAudioSample`。空对象时组装结果为 null |
| `活用形JSON` | jsonb | NOT NULL | `'[]'` | 数组：`[{form, value, example}]` |
| `自他対応JSON` | jsonb | NULL | — | `{intransitive, transitive, particleNote, intransitiveExample, transitiveExample}`。无对应时为 NULL |
| `元レスポンスJSON` | jsonb | NOT NULL | `'{}'` | AI 的原始响应（人工版继承来源版的值）。组装结果的 `structured` 键就是它 |
| `バージョン` | integer | NOT NULL | 1 | 乐观锁 |
| ＋監査列（`登録元コード` 默认 `'BATCH'`） | | | | 版本头里 `登録元コード` 语义是 **`BATCH`=AI 建的版 / `APP`=人建的版** |

**键与索引**

- PK `詳細ID`
- **`uq_jpn_detail_version` UNIQUE (`単語ID`,`内容版数`)**（同词同版本号不重复）
- **`uq_jpn_detail_active` UNIQUE (`単語ID`) WHERE `状態コード='ACTIVE'`**（每词恰好 1 版生效。DB 层保证）
- `idx_jpn_detail_word_state`（`単語ID`,`状態コード`）——取生效版用（一览・详细・AI 输入）
- FK：`単語ID` → `JPN_単語情報`（CASCADE）；`登録者/更新者アカウントID` → `ACC_アカウント`（RESTRICT）

**CHECK**：`状態コード IN (ACTIVE, ARCHIVED)`；`内容版数 >= 1`；`バージョン >= 1`；
`重要度 IS NULL OR BETWEEN 1 AND 5`；`JLPTレベル IS NULL OR IN (N5..N1)`；`自他 IS NULL OR IN (4 值)`；
`jsonb_typeof(発音JSON)='object'`；`jsonb_typeof(活用形JSON)='array'`；`自他対応JSON IS NULL OR object`；`jsonb_typeof(元レスポンスJSON)='object'`。

**写入路径（4 条）**

| 触发 | 新建版的内容 | 版本头 `登録元コード` | 子表行 `登録元コード` | `手修正フラグ` | `生成ID` | `元詳細ID` |
|---|---|---|---|---|---|---|

### 5.14 `v_jpn_word_ai_state`（视图）　AI 取得状态

**用途**：单词信息管理一览的「取得状态（A・B，C，D，E）」列的数据来源。
历史表里同一个「词 × 内容种别」会有多行（重跑），所以视图只保留**最新一行**，
另外给出**是否曾经成功**，让一览能把「以前成功过、最近一次失败」的词仍然显示成「取得済」。

| 列 | 类型 | 说明 |
|---|---|---|
| `単語ID` | bigint | 词 |
| `内容種別コード` | varchar(30) | `A_DETAIL` / `C1_READING` / `C2_KANJI` / `D_CONTEXT_MEANING` / `E_KANJI_USAGE` |
| `状態コード` | varchar(20) | **最新一次**执行的状態 |
| `成功あり` | boolean | 该「词 × 内容种别」是否**曾经** `SUCCEEDED` |
| `生成件数` / `失敗件数` / `エラーコード` / `AI区分` / `モデル名` | | 最新一行的值 |
| `登録日時` / `更新日時` | timestamp | 最新一行的值 |

**排序（决定「最新」）**：`登録日時 DESC`，同秒时用 `生成ID DESC`（确定性）。

**一览 API 的汇总规则**（`JpnWordMapper.xml` 的 LATERAL）：
- 4 个区画：A・B＝`A_DETAIL`／C＝`C1_READING` ＋ `C2_KANJI`／D＝`D_CONTEXT_MEANING`／E＝`E_KANJI_USAGE`
- 区画里**只要有一个内容曾经成功**，该区画返回 `SUCCEEDED`（内容已经落在库里：详细是 UPSERT，题目是 ARCHIVED 保留）
- 否则返回该区画里最新一次的状态（`FAILED` / `RUNNING` / `QUEUED` / `CANCELED`）
- 一次也没跑过 → NULL（画面显示「未取得」）

**画面的用词**（前端 `aiStateLabel.ts`）：`SUCCEEDED`→取得済／`FAILED`→失敗／`RUNNING`→取得中／
`QUEUED`→取得待ち／`CANCELED`→中止／NULL→未取得。

## 7. 关键设计决策与理由

| # | 决策 | 理由 | 代价 |
|---:|---|---|---|
| 1 | **读音可空（`読み` NULL、`読みキー` 空串）** | 登录画面只收集词条，读音交给 AI；让「先登录后补全」成立 | 同一词条在读音确定前可重复；唯一性靠部分索引 |
| 2 | ~~**详情合并进 `詳細JSON`（JSONB）**~~ → **已改为「版本头 ＋ 11 张段落子表」**（2026-09-22） | 当时的理由是「6 张子表只为读一次展示、字段还在演进」；但后来需要**按段落单独编辑**与**保留每次生成的版本**，JSONB 1 列无法表达「哪一行是人改的」 | 表变多（＋11）、每次取得要复制全部段落行；换来版本可回退、人工行不被覆盖（决策 14〜17） |
| 3 | **题目不删只归档（`ARCHIVED`）** | `テスト出題情報.問題ID` 可能引用旧题，删了会断开历史 | 需要归档清理策略 |
| 4 | **出题带「词与详情快照」`単語スナップショットJSON`** | 教材/详情更新后，仍能复现当时的题目与解析 | 存储冗余 |
| 5 | **逐题作答记进 `回答履歴JSON`（数组）** | 一题可能多次作答（重做/订正）；避免再建一张「作答记录」表 | 需要 GIN 索引；单条不能直接 JOIN |
| 6 | **删词 CASCADE 掉学习记录** | 词被删除后其学习状况没有意义 | 误删代价大（画面有确认对话框） |
| 7 | **测试与出题 CASCADE，但收录/问题的引用无外键** | 教材改版、AI 重新生成不应破坏历史记录 | 会出现「悬空引用」，查询要容忍（评审 B3） |
| 8 | **聚合表分三层（词 / 技能 / 日次）** | 三个画面各自需要的粒度不同；比每次实时聚合快 | 三者一致性靠应用保证（评审 B5） |
| 9 | **`旧*` 列 ＋ 唯一索引** | 迁移可重复执行（幂等） | 迁移完成后是历史包袱 |
| 10 | **枚举用 CHECK 而不是码表** | 取值少而稳定，避免多余 JOIN | 改枚举要 DDL（评审 B1） |
| 11 | **语音缓存以「文本＋话者＋速度」为键** | 同一句话跨词/跨题共用，命中率更高 | `対象ID` 只是来源记录，容易误解（评审 B8） |
| 12 | **AI 生成记录按「词 × 内容种别」** | 防重复执行、断点续跑、失败重试 | 列表要显示「取得状态」需额外 JOIN（评审 A4） |
| 13 | **`書籍`（名）＋`書籍ID` 双轨** | 迁移期无法保证名称都对应主数据；名称列让列表在缺 ID 时也能显示 | 冗余、可能不同步（评审 A1） |
| 14 | **版本 = 整词快照**（1 行 = 该词的 1 个完整版，不是段落级差分） | 版本之间可以直接比较、可以整版回退、组装路径只有一条（不需要「按段落合版」的逻辑）；`元詳細ID` 让「从哪一版来」可追 | 每次取得都复制全部段落行，行数按「段落数 × 版本数」增长（历史无限保留，见第 11 章） |
| 15 | **人工编辑也建版**（不是原地 UPDATE） | 误编辑可以一键切回；「谁在什么时候改成了什么」留在库里（`手修正フラグ`・审计列） | 版本数比「只留最新」多得多；需要「历史版本清理策略」 |
| 16 | **人工行不被 AI 覆盖，靠「复制进新版」实现** | 不需要「行级归档」状态列；人想丢掉人工改动时，切回 AI 那一版即可 | 新版里人工行与 AI 行混在一起，看「这版是不是纯 AI」只能看 `登録元コード`（后端用 `manualRows` 汇总成布尔值） |
| 17 | **行的出处（`BATCH`/`APP`）按内容判定，不按 `表示順`** | 画面可以任意重排；同一内容的行换位置后不该变成「人工改过」 | 判定是 O(n²) 的内容比对（段落行数少，可接受）；同一段落里出现两条完全相同的行时，出处会取第一条 |
| 18 | **生效版用「部分唯一索引 ＋ 先归档后插入」** | 「每词 1 版生效」由 DB 保证，应用写错也插不进去 | 写入顺序不能换（必须先 `ARCHIVED` 再插 `ACTIVE`）；不能用「先插后归档」重试 |
| 19 | **选项池（正解 1 ＋ 误答 4〜6）与「作成时抽选固定」分离** | 池越大，题目素材越丰富；但提示的 4 件固定在 `出題選択肢JSON`，所以池被 AI 重新生成也不影响已考记录，画面渲染也不随池大小变慢 | 多一列 JSONB；「哪个干扰项最常被选」这类分析要在 JSONB 上做（要做报表就得改成子表，见第 11 章） |

## 8. 业务流程与表的对应

### 8.1 单词登录（单词信息管理）

1. 画面：`POST /api/user/japanese/words/register`，一次送「词＋教材名＋单元＋SEQ」。
2. 服务端（一条事务）：
   1. **教材主数据**：名称不存在则新建（`書籍コード` = 数字最大 +1，如 `01`→`02`）。
   2. **词**：按（`見出し語キー`,`読みキー`）查；不存在则建（`読み`=NULL、`読みキー`=`''`）。
   3. **收录**：`(単語ID, 書籍ID, 書籍, 分類, 単語SEQ, レベル)`；已存在同词同单元则跳过；
      指定 SEQ 已被占用时顺延到该单元最大 SEQ + 1。
   4. **教材统计**：重算 `分類数`・`収録語数`。
3. 列表：`単語情報` LEFT JOIN「收录代表 1 条」LEFT JOIN「学习状况」，
   排序＝**教材 → 单元 → 单元内顺序 → 词 ID**（没有收录的排最后）。

### 8.2 AI 详细取得（batC41 → `A_DETAIL`）＝**建新版本（含人工行复制）**

1. 选目标：`単語情報` 中「同词同内容种别没有 `SUCCEEDED`」的词（画面可指定，单次最多 50）。
2. 取 AI 设置（设置页 `JAPANESE_WORD_AI` 分类）＋把 **DTO 生成的 JSON Schema** 追加到 System Prompt。
   输入里的「今の詳細」是**生效版组装后的 JSON**（`JapaneseWordAiDetailReader`），与画面看到的同形。
3. 调用 AI（同步）。1 次调用 = 1 行 `BAT_AI呼出履歴情報`，返回**採番后的 `呼出履歴ID`**。
4. 校验：语义词 ≥ 1、例句 ≥ 2、搭配 ≥ 2，否则 `THIN_CONTENT` 失败并重试。
5. **建新版本**（一条事务，`JapaneseWordAiDetailWriter.createVersion`，顺序不可换）：
   1. 读当前生效版（＝`元詳細ID` 的来源，没有则是初版）
   2. 数出**人工行的最大 `表示順`**（`countKeptDetailRows`），AI 的行接在它后面
   3. 当前生效版 → `ARCHIVED`（**不删**）
   4. 插入新版本头：`ACTIVE`・`内容版数` = 该词最大 + 1・`生成ID` = 本次・`AIプロバイダ`／`AIモデル`・`取得日時`・`登録元コード='BATCH'`
   5. **把人工行复制进新版**（`copyDetailDialogs` → `copyDetailDialogLines` 的顺序；会話行改挂新的 `会話ID`）
   6. 插入 AI 的新行（11 张子表；`表示順` = 复制的最大值 + 段落内位置）
6. `markGenerationSucceeded`：`AI生成履歴情報` 置 `SUCCEEDED`，写入 **`呼出履歴ID`**（切片3 修好的缺陷）与 `生成ID` 的对应。
7. **读音回填**：若该词 `読み` 为空且有 `pronunciation.reading`，写入 `読み`・`読みキー`（已有读音不覆盖）。
8. **JLPT 级别回填**：若该词 `JLPTレベル` 为空且 AI 的 `jlpt` 是 `N1`〜`N5`，写入 `単語情報.JLPTレベル`
   （已有级别不覆盖，非法值跳过并记日志）。这样「按 JLPT 筛选」才有数据。
9. 逐词的执行结果写进 `BAT_バッチ実行履歴情報` / `BAT_AI呼出履歴情報`；一览的「取得状态」列从
   `v_jpn_word_ai_state` 取（见 5.14）。

> **失败时什么都不留下**：整条路径在一个事务里，中途失败不会产生「半个版本」。
> **人工行去哪了**：被复制进新版，所以不会因为 AI 重取而消失。想回到人工内容，切回人工那一版（8.4b）。

### 8.2b 画面编辑保存 ＝**建人工版**

`PUT /words/{wordId}/editor`（`saveWordEditor`。整份详细一次保存，**没有段落级 API**，见评审 A6）：

1. 校验 `contentVersion`（画面读到的详细版数）与生效版一致，不一致 409。
2. `JpnWordDetailEditorComposer.compose`：把画面送来的详细崩成新版的头 ＋ 11 张子表的行。
   - **行的出处按内容判定**：与来源版内容完全相同的行**沿用原出处**（`BATCH`/`APP` 都不变）；
     改动过或新增的行标 `APP` 且 `手修正フラグ`=true；来源版有、画面没送的**行删除**。
   - 语级值：要求里有就用要求的值，没有的键沿用来源版（画面只送一部分也不会把内容抹掉）。
   - 版本头：`元詳細ID`=当前生效版・`生成ID`=NULL・`手修正フラグ`=有任人工行・`登録元コード='APP'`・
     `AIプロバイダ`／`AIモデル`／`元レスポンスJSON` 从来源版继承（人工编辑不改变「哪个 AI 生成的」）。
3. 当前生效版 → `ARCHIVED`；插入新版本头（`ACTIVE`）；插入全部子表行。
4. 同事务更新母表 `単語情報`（用 `単語情報.バージョン` 做乐观锁），任一步失败全部回滚。

> 结果：**没碰过的 AI 行，在下一次 AI 取得时照旧被替换；碰过的行不会再被 AI 覆盖。**

### 8.2c 版本一览与切换生效版

- `GET /words/{wordId}/detail-versions`：该词的全部版，**新版在前**（`内容版数 DESC, 詳細ID DESC`）。
  每行返回 `contentVersion`・`stateCode`・`active`・`manual`・`aiProvider`・`aiModel`・`generationId`・
  `fetchedAt`・`note`・`createdAt`/`updatedAt`・**10 个段落的行数**（`counts`。「哪一版内容更多」在画面上能看出来）。
- `PUT /words/{wordId}/detail-versions/{detailId}/active`：把 `ACTIVE` 移到指定版。
  **不新建版**；同事务先把当前生效版 `ARCHIVED` 再把这版设 `ACTIVE`；`バージョン` 不一致则 409。
- 未指定时＝最后新建的那版生效（所有写入路径都以 `ACTIVE` 出生，所以不需要额外代码）。
- 前端面板 `JpnDetailVersionPanel.vue` 显示 `版 N`・「生效中」・「人が作成／AI が作成」・取得时刻・各段落行数；
  按「この版を使う」调用上面的 PUT。

> **已修（评审 A7，2026-09-22）**：版一览与详情 API 现在返回该版的 `バージョン`，前端切换时送它。

### 8.3 题目生成（batC42〜44 → `C1_READING`,`C2_KANJI`,`D_*`,`E_*`）

1. 目标选取/防重复同 8.2。
2. C 类一次生成两题（C1 表记→读音、C2 读音→表记）；D/E 各一题。
3. 校验（切片6 起）**选项池规则**：合计 **5〜7 件**、**正解恰好 1 件**、值互不重复、正解行 `誤答区分` 为 NULL。
   不满足则**整题不合格、一行不写**（失败记在 `JPN_AI生成履歴情報`）。
   正确答案强制取「输入词」（C1=输入读音、C2=输入表记）；**读音为空时用 AI 的读音**（2026-09-22）。
4. 写库：同词同种别的旧 `ACTIVE` → `ARCHIVED`，插入新题与 **5〜7 个选项**（池）。

### 8.4 测试作成（从池抽 3 误答＋1 正解、打乱、固定到 `出題選択肢JSON`）

1. `テスト情報` 1 行（类型/范围/题数/检索条件快照）。
2. 出题对象：
   - **C/D/E**：`pickQuestions` 从 `問題情報` 取题（`状態コード='ACTIVE'`，按种别・难度・范围）。
     对每题读**选项池**（`listChoices`）→ 取**正解 1 ＋ 误答随机 3** → **打乱顺序** → 存成
     `出題選択肢JSON`（`[{choiceId,value,reading,correct}]`）。
     **池不足（正解 ≠ 1 件，或误答 < 3 件）则「条件に合う問題がありません」并中止整次作成**（不写半套题）。
   - **A/B**：没有题库，从别的词（同条件）取误答，组成同形的 4 件写 `出題選択肢JSON`（`choiceId` 为 null）。
     判定路径只有一条。
3. 打开测试 `GET /tests/{testId}`：**返回固定的这 4 件（`出題選択肢JSON`），不再返回整个池**；
   没有该列值的旧数据才回退读池。
4. 作答：更新 `出題情報`（`出題状態`・判定・计数・`回答履歴JSON` 追记）。判定读 `出題選択肢JSON`
   （选中项的 `correct` ＋ 与 `正解値` 双重确认）；选中的选项不在本次提示里则 400。
5. 状况更新：`学習状況情報`（词级）＋ `技能習得情報`（技能级，**A 不写这行**）＋ `学習日次情報`（当天时间与计数）。
6. 完成：`テスト情報` 置 `COMPLETED`，汇总计数与有效学习时间。

> **A 类不写技能行的原因（已修的缺陷，见评审 A8）**：`JPN_技能習得情報` 的 CHECK 只允许 B〜E 的技能区分，
> A 写进去会违反 `CK_JPN_技能習得_種別と技能`。现在 `updateLearning` 用 `tracksSkill(testType)` 对 A 直接跳过技能行，
> 学习状况与日次照常更新，A 的确认次数记在 `学習状況情報.A確認回数`。

### 8.5 语音（设计已定，API 未实现）

请求朗读 → 计算 `音声キー` = SHA-256(文本＋话者＋速度) → 命中 `READY` 行则直接返回文件；
未命中则调用外部 TTS、落盘（相对路径）并插入 `READY` 行；失败记 `FAILED` 与错误码。
长期未用（`idx_jpn_audio_unused`）的可删实体、置 `EXPIRED` 保留行。

## 9. 一致性与并发

| 主题 | 做法 |
|---|---|
| 乐观锁 | `単語情報`・`テスト情報`・`書籍情報` 有 `バージョン`。画面修改必须带上版本，被抢先修改时返回冲突 |
| 悲观/唯一约束 | 迁移幂等靠 `旧*` 唯一索引；业务唯一靠部分唯一索引与复合主键 |
| 计数列 | 全部由 CHECK 约束保证非负与单调关系（如 `完了出題数 <= 出題数`）。**应用侧负责重算，DB 只校验** |
| 时间 | 不手写时间戳：`登録日時/更新日時` 由默认值与 UPDATE 语句设置 |
| 审计 | 所有表带 6 列审计；批处理写入时 `登録元コード='BATCH'`，操作者为 NULL |
| DB 操作日志 | 所有访问必须走 MyBatis（`SqlLoggingInterceptor` 记 SQL 日志）。**禁止绕过 ORM 直接 JDBC**（会漏日志） |
| 并发登录同一新教材 | 应用侧用「数字最大 +1」编号，**没有唯一保护**：同一新名称并发注册可能产生 2 行（评审 A1 备注） |
| 并发 AI 执行 | `JPN_AI生成履歴情報` 的部分索引 `idx_jpn_ai_gen_active` 用于「已有进行中的行就复用」，避免同一词重复跑 |

## 10. 设计评审：问题与改进建议

> 这一章是中文版新增的。**结论：整体骨架可用（词为中心、AI 产物与业务数据分离、聚合分粒度），
> 但有 5 个结构性问题值得修，另外有一批一致性/卫生问题。**
> 每条给出「现象 → 影响 → 建议 → 迁移代价」。
>
> **实施状况（2026-09-22）**：**A2・A3・A4 已实施**（下面各条带【已实施】标记，详细做法见对应章节）；
> **本次（切片 7）新增 A6・A7・A8**（A6 是「设计上接受」、A7 与 A8 均为**已修**）。
> **另外：收工前的两轴审查又发现并修掉了 4 个问题**（A7 的字段语义、`Integer` 引用比较、并发保存的 409、batC42 重复写题），见 §10 的 A7・A8 与 §12 变更历史。
> A1・A5 与 B/C 级仍为待办。

### A 级：结构性问题（建议尽早修）

**A1. 教材是「名称 + ID」双轨，且 ID 可为空**（**未实施**）

- 现象：`JPN_単語収録情報` 同时有 `書籍`（名称，NOT NULL）与 `書籍ID`（FK，**NULL 允许**）。
- 影响：改名要改两处、可能不同步；`書籍ID` 为空时收录成为「孤儿」，按教材 ID 的统计/筛选会漏。
- 建议（择一）：
  1. **推荐**：`書籍ID` 回填后改为 NOT NULL，名称列降级为「缓存列」，由服务层或触发器同步；
     列表查询改为 JOIN `書籍情報` 取名称。
  2. 或：删掉名称列，只留 ID（迁移期多做一次回填与代码调整）。
- 迁移代价：中（1 条回填 UPDATE ＋ `ALTER COLUMN SET NOT NULL` ＋ 3 处查询调整）。
- 现状：本库 345 行 `書籍ID` **已全部填好**，是做这件事的最佳时机。

**A2. JLPT 级别三处语义重叠，且都不好用**　**【已实施 2026-09-22】**

- 现象：① `単語情報.JLPTレベル`（当时全 NULL）② `収録情報.レベル`（**全 `N1-N5`**，实为教材级别带）
  ③ 详细版本头的 `JLPTレベル` 列（AI 给的真实级别。旧称 `詳細JSON.jlptLevel`）。
- 影响：画面「按 JLPT 筛选」永远筛不出东西。
- **已做的**：确定词级级别真源为 `単語情報.JLPTレベル`，**batC41 成功后像读音一样回填**
  （`JapaneseWordAiMapper.updateJlptIfBlank`；只接受 `N1`〜`N5`，非法值跳过不写；
  已有级别不覆盖）。`収録情報.レベル` 保留为「教材级别带」，其含义在 5.3 写明。
- **仍待办**：`収録情報.レベル` 是否改名为 `レベル帯`（避免再被当成词级级别）。

**A3. （教材, 单元, 顺序）没有唯一约束**　**【已实施 2026-09-22】**

- 现象：`JPN_単語収録情報` 只有普通索引 `idx_jpn_collect_book`，无 UNIQUE。
- 影响：同一本书同一单元可能出现两条「第 5 位」，导致列表顺序不稳定、教材页码对不上。
- 建议：查重后加**部分唯一索引**（只对 `状態コード='ACTIVE'`）：
  `UNIQUE ("書籍ID","分類","単語SEQ") WHERE "状態コード"='ACTIVE'`。
  应用侧已有「SEQ 被占用就顺延」的保护，加索引后可彻底防住。
- **已做的**：查重（0 件）后建了 `uq_jpn_collect_position`
  （`書籍ID`,`分類`,`単語SEQ`）WHERE `状態コード='ACTIVE' AND 書籍ID IS NOT NULL`（`UPD_JPN_単語収録情報_位置の一意.sql`）；
  应用侧遇唯一键冲突自动顺延一次（服务层捕获 `DuplicateKeyException`）。

**A4. 列表要显示的「AI 取得状态」不在词表上**　**【已实施 2026-09-22】**

- 现象：判断某词是否已生成，必须查 `JPN_AI生成履歴情報`（且要按内容种别聚合）。
- 影响：单词信息管理的「取得状态」列永远显示「未取得」（画面没有数据来源）。
- 建议（择一）：
  1. **推荐**：建视图 `v_jpn_word_ai_state`（`単語ID` × 内容种别 → 最近状态），列表 JOIN 视图；
  2. 或在 `単語情報` 加缓存列（`A_DETAIL状態コード` 等），由批处理更新。
- **已做的**：选了方案 1 —— 视图 `v_jpn_word_ai_state`（最新一行 ＋ 是否曾经成功，见 5.14）
  → 一览 SQL 的 LATERAL 汇总成 4 个区画 → API 返回 `aiState` → 画面显示
  「取得済／失敗／取得中／未取得」（前端 `aiStateLabel.ts`）。词表没有加缓存列。

**A5. 「课题」概念已废弃，但列名还在，口径与计数列重叠**

- 现象：`学習日次情報` 保留 `完了課題数/正解課題数/不正解課題数`（2.0 的「课题」= 一个词的一次作答），
  与 `テスト情報.正解数/不正解数`（口径是题数）语义相近但不同。
- 影响：写统计代码的人容易取错列；B 类一个词两题时数字对不上（`正解数` 可超过 `出題数`）。
- 建议：统一口径命名 —— 例如日次改为 `完了出題数/正解出題数/不正解出題数`，
  或在视图层暴露统一命名，并在文档里写明「课题=出题」。
- 迁移代价：低～中（列改名脚本 ＋ 应用 2 处）。

**A6. 段落级编辑 API 暂缓，用「整份保存 ＋ 按内容判定出处」代替**　**【已实施（替代方案）】**

- 规格原本要求「按段落单独编辑／单独重取」（再设计案 §1.4 的「画面编辑保存（按段落）」与新增段落级编辑 API）。
- **实际做法**：`PUT /words/{wordId}/editor` **一次送整份详细**（`JapaneseModels.WordEditorRequest` 的 `detail` 是整块 Map），
  服务端用 `JpnWordDetailEditorComposer` 把「内容相同的行」判定为「没被改过」，沿用它原来的出处（`BATCH`/`APP`）。
- **为什么可以这样**：
  1. 「人工行不被 AI 覆盖」这个**结果**是靠行的 `登録元コード`/`手修正フラグ` 表达的，不靠「哪个 API 调的」。
  2. 一次请求就是一条事务，不存在「段落 A 保存成功、段落 B 失败」的中间态。
  3. 前端（`editorStore.ts`）本来就是本地 draft 全量重建 payload，拆成段落 API 反而要维护「哪些段落脏了」。
- **代价（承认的）**：
  1. 请求体比「只送一段」大（现在是整份详细）。
  2. 「同段落里两条完全一样的行」无法区分谁被改过（判定取第一条）。
  3. **无法只对某一段落重新调用 AI**（现在每次 AI 取得都是整词快照）。这就是第 11 章「段落级 AI 批处理（`A_EXAMPLES` 等）」的由来。
- **将来要做段落级 API 时**：把 `compose` 按 `JpnWordDetailChildren.Rows` 的 11 个字段切开（它已经是按段落分别处理的），
  再给请求加「要替换哪个段落」的参数即可，DB 侧不需要改。

**A7. 版本一览不返回 `バージョン`，与「切换生效版」的乐观锁要求不一致**　**【已修（2026-09-22，两轴审查发现后当场修复）】**

- 现象（读代码得到的事实）：
  - 后端 SQL `listDetailVersions` 的 `DetailVersionColumns` **SELECT 了 `d."バージョン"`**，MyBatis 也把它装进
    `JpnWordDetailVersionEntity.version`（`DetailVersionMap` 里有这一行的映射）；
  - 但 `JapaneseServiceImpl.toVersionRow` 组装 DTO `DetailVersionRow` 时**没有把它放进 record**，前端 `JpnDetailVersion` 也没有 `version` 字段；
  - 而 `PUT /words/{wordId}/detail-versions/{detailId}/active` 的 `ActivateVersionRequest.version` 在服务端是拿来和
    **被切换目标版（`findDetailVersion` 取到的历史版）的 `バージョン`** 比较的（`target.getVersion() != request.version()` → 409，条件 UPDATE 也是 `AND "バージョン" = #{version}`）。
- 现状的实际行为：前端 `JpnDetailVersionPanel.vue` 送的是**当前已加载详细版的 `内容版数`（`contentVersion`）**，
  与目标历史版的 `バージョン` 是**两个不同的量**。`JPN_単語詳細情報."バージョン"` 默认 1，而 `insertDetailVersion` 不写这列、
  只有「切换生效版」的 UPDATE 会 `+1`，所以目标历史版的 `バージョン` 通常恒为 1 → 只要当前详细版不是第 1 版，就会**误报 409**。
- 单测为什么没抓到：`JapaneseServiceImplTest` 把夹具的 `entity.setVersion(3)` 硬编码，请求也传 3，于是「两边相等」这个巧合成立了。
- 影响：**「切回旧版」这个功能在真库上很可能一直报 409**（每次 `contentVersion != 1` 时）。
- 建议（择一，都需要改代码，本次只记录）：
  1. **把 `バージョン` 加进 `DetailVersionRow` 与前端 `JpnDetailVersion`**，面板送目标的 `バージョン`（语义最正，改动最小）。
  2. 或把「切换生效版」的乐观锁改成用**当前生效版的 `バージョン`**（`activateDetailVersion` 也把 `wordId` 的条件带上），
     请求语义变成「我基于哪个生效版在切」。
  3. 或去掉这一处的乐观锁（切换是幂等操作，重复切到同一版无害），只留审计列留痕。
- 附带：`JapaneseTestView.vue` 的 `mergeTest()` 把本地 `judgment` 写成 `'WRONG'`，而后端产出的是 `'INCORRECT'`；
  同一次会话里 `isWrong` 的两个判定条件因此要用两个值，属同类「同一概念两个值」的问题，一并记录。

**A8. A 类作答会违反 `CK_JPN_技能習得_種別と技能`**　**【已修（切片 4/5 期间发现并修好）】**

- 现象：`JPN_技能習得情報` 的 CHECK 只允许 B〜E 的技能区分（`B_ORTHOGRAPHY`/`B_READING_RECALL`/`C_READING_RECOGNITION`/`C_KANJI_RECOGNITION`/`D_CONTEXT_MEANING`/`E_KANJI_USAGE`）。
  A（勉強）没有技能区分，但作答处理是共用的，于是 A 也会去插一行技能。
- 影响：A 类测试一作答就报 CHECK 违反（500），学习状况与日次也一起回滚。
- **已做的**：`JapaneseServiceImpl.updateLearning` 用 `tracksSkill(testType)`（`!"A".equals(testType)`）判断，
  A **不写 `JPN_技能習得情報`**；词级状况与日次照常更新；A 的确认次数继续记在 `学習状況情報.A確認回数`。
  `SKILL_CODES` 这个「问题种别 → 技能区分」的 Map 里**故意不放 A**，注释写明原因。
- 还要注意：`refreshStatusFromSkills` 仍会被调用，A 的时候传「A 确认次数 +1」的标记（`"A".equals(testType) ? 1 : 0`），
  让 A 的确认次数不被技能平均覆盖成 0。
