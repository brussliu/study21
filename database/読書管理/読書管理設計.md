## 2. テーブル設計

### `RED_書籍情報`（本棚 1 冊 = 1 行）

| 列 | 型 | 意味 |
|---|---|---|
| `書籍ID` | BIGSERIAL PK | 2.1 の内部 ID。記録・標記はこれで親を参照する |
| `書籍番号` | VARCHAR(30) UNIQUE | 利用者に見せる番号。2.0 の `書籍ID`（`ER-yyyyMMdd-HHmmss`）をそのまま引き継ぐ |
| `言語` | VARCHAR(20) | **`中国語` / `英語` / `日本語`**（利用者の指示で追加）。分類はジャンルだけを持ち、言語はこの列で表す |
| `公開範囲コード` | VARCHAR(20) NOT NULL DEFAULT `'FAMILY'` | **2026-09-14 追加**。`GLOBAL`=管理者が登録した全体書籍（全家庭の【図書館】に出る）/ `FAMILY`=家庭の中だけの書籍 |
| `所有家族学生ID` | BIGINT FK NULL | **2026-09-14 追加**。`FAMILY` のときの持ち主の家庭（＝生徒の `アカウントID`）。`GLOBAL` は NULL（`CK_RED_書籍_公開範囲と所有` で強制）。`ACC_アカウント` へ `ON DELETE RESTRICT` |
| `分類ID` | BIGINT FK | 本棚の分類（`RED_書籍分類情報`）。NULL は未分類。分類を削除すると NULL に戻る |
| `教科` | VARCHAR(20) | 2.0 から引き継いだ列（実データは全件 `'英語'`）。**画面では使わない**（言語 を使う） |
| `書籍名` / `作者` | VARCHAR | 一覧・閲覧に表示する |
| `難易度` | VARCHAR(20) | `Starter` / `Elementary` / `Intermediate` / `Upper` |
| `読書ステータス` | VARCHAR(20) | `未着手` / `読書中` / `一時停止` / `読了` |
| `総ページ数` | INTEGER | 本の総ページ数（2.0 は PDF 原本のページ数。159〜1515） |
| `現在ページ` | INTEGER | 最後に読んだページ |
| `置頂フラグ` | BOOLEAN | true を一覧の先頭に出す |
| `タグ` | TEXT | カンマ区切り（`Novel,Classic`）。**未設定は NULL**（2.0 の空文字は移行時に NULL へ） |
| `概要` | TEXT | 読書方針・概要 |
| `最近の読書時間分` | INTEGER | 直近 1 回の読書時間（分） |
| `累計読書時間分` | INTEGER | 累計の読書時間（分） |
| `累計標記件数` | INTEGER | 全ページの標記件数（2.0 の集計値を引き継ぐ） |
| `最終読書日時` | TIMESTAMP | 最後に読書記録を付けた日時 |
| `備考` | TEXT | 自由記入 |
| `バージョン` | INTEGER | 楽観的ロック（画面からの修正で使う） |
| `登録者/更新者アカウントID` | BIGINT FK | `ACC_アカウント` への FK（引けない 2.0 の ID は NULL） |
| `登録元/更新元コード` | VARCHAR(20) | `APP`=画面 / `MIGRATION`=2.0 からの移行 |
| `登録日時` / `更新日時` | TIMESTAMP NOT NULL | |

- **本は「公開範囲」を持つ（2026-09-14 の決定）**: `GLOBAL`＝管理者が登録した全体書籍
  （全家庭の【図書館】に出る）／`FAMILY`＝保護者が登録した家庭の本（その家庭の保護者・生徒にだけ出る）。
  **管理者は家庭を持たないので `GLOBAL` だけが見える**。見える条件は「`GLOBAL` ∪ 自分の家庭」で、
  一覧・件数・サマリ・分類の冊数・PDF 配信のすべてに同じ条件を当てる（当て忘れると画面の冊数だけが
  食い違う）。本を誰が持っているかは `RED_自分の本棚情報`（アカウントごと）。
  誰が登録したかは `登録者/更新者アカウントID` に残す。
- 制約: `難易度`・`読書ステータス` の CHECK、`総ページ数 >= 1`、`現在ページ >= 1`、
  時間・件数 >= 0、`バージョン >= 1`、登録者/更新者は `ACC_アカウント` への FK（`ON DELETE RESTRICT`）。
  2.0 にあった `現在ページ <= 総ページ数` の CHECK は**外した**
  （サービス側で丸める。ページ数の訂正で既存データが弾かれないようにするため）。
- 索引: `書籍番号` UNIQUE（`uq_red_book_no`）／
  一覧 `置頂フラグ DESC, 最終読書日時 DESC NULLS LAST, 書籍ID DESC`（`idx_red_book_shelf`）／
  絞り込み `教科, 難易度, 読書ステータス`（`idx_red_book_filter`）／
  名称検索 `教科, 書籍名`（`idx_red_book_name`）。

### `RED_読書記録情報`（1 回の読書 = 1 行）

| 列 | 型 | 意味 |
|---|---|---|
| `記録ID` | BIGSERIAL PK | 2.0 の `記録SEQ` は持ち込まない |
| `書籍ID` | BIGINT NOT NULL FK | `RED_書籍情報` へ `ON DELETE CASCADE`（本を消したら記録も消える） |
| `読書日時` | TIMESTAMP NOT NULL | 今回の読書を記録した日時 |
| `開始ページ` / `終了ページ` | INTEGER NULL | 今回読んだ範囲（`終了 >= 開始` の CHECK） |
| `読書時間分` | INTEGER NOT NULL | 今回の読書時間（分）。0 以上 |
| `標記件数` | INTEGER NOT NULL | 今回追加・更新した標記の件数。0 以上 |
| `メモ` | TEXT NULL | 今回の読書メモ |
| 監査列 | | `登録者/更新者アカウントID`・`登録元/更新元コード`・`登録日時`・`更新日時` |

- 索引: 書籍ごとの履歴（新しい順）`書籍ID, 読書日時 DESC, 記録ID DESC`／
  全書籍の履歴 `読書日時 DESC, 記録ID DESC`（書籍管理画面の「読書履歴」）。
- 記録を付けると `RED_書籍情報` 側も**同じトランザクションで**更新する:
  `現在ページ` / `最近の読書時間分` / `累計読書時間分` / `累計標記件数` / `最終読書日時` /
  `読書ステータス`（`未着手` なら `読書中` へ）。

### `RED_標記情報`（ページ上の 1 標記 = 1 行）

| 列 | 型 | 意味 |
|---|---|---|
| `標記ID` | BIGSERIAL PK | 2.0 の `標記SEQ` は持ち込まない |
| `書籍ID` | BIGINT NOT NULL FK | `RED_書籍情報` へ `ON DELETE CASCADE` |
| `ページ番号` | INTEGER NOT NULL | 1 以上。**2.0 の本文 PDF のページ番号**をそのまま使う |
| `標記種別` | VARCHAR(20) NOT NULL | `highlight` / `underline` / `memo` / `vocabulary` / `pen` |
| `対象文字` | TEXT NULL | ハイライト・下線の対象文字列、語彙の見出し語 |
| `標記内容` | TEXT NULL | メモ本文・語彙の意味 |
| `色` | VARCHAR(20) NULL | 表示色（`#rrggbb`） |
| `太さ` | INTEGER NULL | 手書き・線の太さ（1 以上） |
| `位置X` `位置Y` `幅` `高さ` | NUMERIC(10,6) NULL | **2.0 の PDF 重ね表示用の相対座標（0-1）。2.1 の表示では使わない** |
| `描画データ` | TEXT NULL | **2.0 の手書きパス・拡張 JSON。2.1 の表示では使わない** |
| `表示順` | INTEGER NOT NULL | 同じページの中での並び順（1 から） |
| 監査列 | | 記録と同じ |

- 索引: 閲覧画面が引く `書籍ID, ページ番号, 表示順, 標記ID`／
  種別の絞り込み（語彙ピックアップ）`書籍ID, 標記種別, ページ番号`。
- **位置X/位置Y/幅/高さ/描画データ は PDF の上に標記を重ねるために使う（§3・§4）。**
  値は**ページ内の正規化値（0〜1、左上原点）**。移行した 838 件はすべて値を持っており
  （実測。`描画データ` は `{"kind":"selection","rects":[{x,y,width,height},…],"note":…}` の形）、
  本 3 と 5 の標記がそのまま PDF の該当ページに重なる。

### `RED_書籍分類情報`（本棚の分類。2026-09-13 追加）

| 列 | 型 | 内容 |
|---|---|---|
| `分類ID` | BIGSERIAL PK | |
| `分類名` | VARCHAR(50) NOT NULL | 本棚に出す名前（例 `英語 小説` / `中国語`）。前後の空白は落とす。**一意は「家庭の中で」**（`uq_red_category_name_scope` ＝ `(COALESCE("所有家族学生ID", 0), "分類名")`） |
| `所有家族学生ID` | BIGINT FK NULL | **2026-09-14 追加**。NULL＝全体の分類（管理者が作り全家庭に見える）／値あり＝その家庭だけの分類。`ACC_アカウント` へ `ON DELETE RESTRICT` |
| `表示順` | INTEGER NOT NULL DEFAULT 0 | 棚の並び順（小さいほど先頭。同じ値は `分類ID` 順） |
| `説明` | TEXT NULL | 棚の補足 |
| 監査列 | | 記録と同じ |

- **分類はマスタで、本に付ける値は 1 つ**（`RED_書籍情報.分類ID`）。タグ（複数・自由入力）は
  検索の補助として残し、分類は「棚の区切り」に使う。
- **分類を消しても本は消さない**（`ON DELETE SET NULL` → 本は「未分類」に戻る）。
- 階層は持たない（親分類ID は作らない）。冊数が多くないので、並べ替えで足りる。
- 初期値（移行で投入し、そのあと 2026-09-13 の指示でジャンルだけに整理）: **`小説`(5 冊) / `雑誌・ガイド`(1 冊)**。
  言語は分類ではなく `RED_書籍情報.言語` で表す（`中国語` という分類は廃止し、射鵰英雄伝 は
  `小説` ＋ `言語='中国語'` になった）。
- 分類の追加・改名・削除は**書籍編集ダイアログの「＋ 新しい分類を追加…」**から行う
  （書籍管理のタブ行には管理ボタンを置かない。利用者の指示）。

### `RED_自分の本棚情報`（アカウントごとの本棚。2026-09-14 追加）

| 列 | 型 | 内容 |
|---|---|---|
| `本棚ID` | BIGSERIAL PK | |
| `アカウントID` | BIGINT NOT NULL FK | 本棚の持ち主（生徒・保護者・管理者のいずれか 1 アカウント）。`ACC_アカウント` へ `ON DELETE RESTRICT` |
| `書籍ID` | BIGINT NOT NULL FK | 入れた本。`RED_書籍情報` へ **`ON DELETE CASCADE`**（本を消したらみんなの本棚からも消える） |
| `表示順` | INTEGER NOT NULL DEFAULT 0 | 第 1 版は使わない（並びは本の `置頂フラグ` → `最終読書日時`） |
| 監査列 | | 記録と同じ（`登録元コード` は `APP`。`MIGRATION` は今回使わない） |

- **`UNIQUE (アカウントID, 書籍ID)`** なので【本棚に入れる】は `ON CONFLICT DO NOTHING` で**冪等**。
- 本棚は**アカウント単位（個人）**（決定 Q2）。家族で共有したい要求が出たら `アカウントID` を
  家族学生ID に読み替えるだけで、家庭の解決 SQL はそのまま使える。
- **初期状態は空**（決定 D3）。既存アカウントへ一括投入しない（画面に空の案内を出す）。
- 保護者が登録した本は**登録した本人の本棚にだけ**自動で入る（決定 Q5。家庭の他の人は【図書館】から入れる）。
- アカウントの物理削除は「本棚 → その家庭の書籍 → アカウント」の順に行う（`RESTRICT` のため）。

### `RED_書籍ファイル情報`（本文 PDF と表紙。2026-09-13 追加）

| 列 | 型 | 内容 |
|---|---|---|
| `ファイルID` | BIGSERIAL PK | |
| `書籍ID` | BIGINT NOT NULL FK | `RED_書籍情報` へ `ON DELETE CASCADE` |
| `ファイル区分` | VARCHAR(20) NOT NULL | `PDF`=本文 / `COVER`=表紙。**UNIQUE (`書籍ID`, `ファイル区分`)**＝1 冊 1 件ずつ |
| `元ファイル名称` | VARCHAR(255) NULL | 利用者が選んだ元の名前（画面に「どのファイルか」を出す） |
| `保存ファイル名` | VARCHAR(255) NOT NULL | ストレージ上の名前（2.1: `<書籍番号>-<uuid8>.pdf` / 2.0: `20260402-124745-…pdf`） |
| `保存パス` | VARCHAR(255) NOT NULL | **相対**ディレクトリ（末尾 `/`）。2.1 は `books/<書籍番号>/`、2.0 は `file/ENGLISH_READING/<yyyyMM>/` |
| `MIME_TYPE` | VARCHAR(100) NULL | |
| `ファイルサイズ` | BIGINT NULL | 2.0 の `COM_ファイル情報` にサイズ列が無いため移行分は NULL |
| `ページ数` | INTEGER NULL | PDF の総ページ数（画面が pdf.js で数えて送る） |
| 監査列 | | 記録と同じ |

- **絶対パスを持たない**（配備先で動かなくなるため）。実体の場所はストレージの設定が決める。
- **実体が無くても行を作る**（2.0 のメタ情報を捨てないため）。表示時に実体の有無を確認し、
  無ければ `GET /books/{id}/pdf` は 404、画面は「PDF 未登録」を出す。
- 表紙は一覧のカードに出す（`GET /books/{id}/cover`）。

| 列 | 型 | 内容 |
|---|---|---|
| `辞書ID` | BIGSERIAL PK | |
| `言語` | VARCHAR(20) NOT NULL | `中国語` / `英語` / `日本語`（引き当ての向きを決める） |
| `見出し語` | VARCHAR(100) NOT NULL | **正規化した語**（前後空白除去・英字は小文字化）。`UNIQUE (言語, 見出し語)` |
| `日本語訳` | TEXT NULL | 英語の本の「語彙」で使う（ExcelAPI enja） |
| `中国語訳` | TEXT NULL | 英語の本の「語彙」で使う（有道） |
| `ピンイン` | VARCHAR(200) NULL | 中国語の本の「読み方」で使う（有道 `phone`） |
| `解説` | TEXT NULL | 中国語の本の「読み方」で使う（有道の中国語解説・英語対訳） |
| `取得元コード` | VARCHAR(50) NOT NULL | `EXCELAPI` / `YOUDAO` / `GOOGLE` / `AI` / `MANUAL` |
| `取得日時` / `更新日時` | TIMESTAMP | |

- **利用者のデータではないので監査列（登録者アカウントID 等）は持たない**（キャッシュ）。
- 引けなかったときは**行を作らない**（次に開いたときにまた試せるように）。
- 外部サービスは 2.0 と同じ（`api/word/translateByAi` の実体＝ExcelAPI / 有道 / Google 翻訳）。
  2.1 は結果をここへ貯めるので、**一度引いた語はオフラインでも出せる**。

### 2.0 から変えた点

| # | 2.0 | 2.1 | 理由 |
|---|---|---|---|
| 1 | 主キーが業務キー（`書籍ID='ER-…'`）／`記録SEQ`・`標記SEQ` | `書籍ID` は BIGSERIAL、2.0 の ID は `書籍番号` として残す | 2.1 の規約（内部 ID は BIGSERIAL、業務キーは別列） |
| 2 | 子（記録・標記）が `書籍ID`（VARCHAR）で親を参照 | `書籍ID`（BIGINT FK）＋ `ON DELETE CASCADE` | 親を消したときの後始末を DB に任せる。移行時に `書籍番号` 経由で読み替える |
| 3 | `登録ID` / `更新ID` は自由文字列 | `登録者/更新者アカウントID`（FK）＋ `登録元/更新元コード` | 2.1 の監査規約 |
| 4 | 楽観的ロックなし | `バージョン` | 画面からの修正で使う |
| 5 | `現在ページ <= 総ページ数` の CHECK | `現在ページ >= 1` だけ | ページ数の訂正で既存データが弾かれないようにする |
| 6 | PDF・表紙を `COM_ファイル情報`（機能区分で共用）で参照 | **`RED_書籍ファイル情報`**（1 冊 1 PDF・1 表紙）＋ストレージ | モジュールごとに自分のファイル表を持つ方針（資料管理と同じ）。共用表だと他機能の都合で列が増える |
| 7 | 分類という概念が無い（タグと難易度だけ） | **`RED_書籍分類情報`**（マスタ）＋ `分類ID` | 本棚から素早く探せるようにする（利用者の指示） |
| 8 | 言語の概念が無い（`教科='英語'` 固定で、中国語の本も `タグ='中国語'` で区別） | **`言語`**（`中国語` / `英語` / `日本語`）＋ 分類はジャンルだけ | 「英語 小説」「中国語」のような言語混じりの分類をやめ、言語は専用の列で選ぶ（利用者の指示） |

### コード値

| 列 | 値 |
|---|---|
| `言語` | `中国語` / `英語` / `日本語` |
| `難易度` | `Starter` / `Elementary` / `Intermediate` / `Upper` |
| `読書ステータス` | `未着手` / `読書中` / `一時停止` / `読了` |
| `標記種別` | `highlight`=ハイライト / `underline`=下線 / `memo`=メモ / `vocabulary`=語彙 / `pen`=手書き |
| `登録元コード`・`更新元コード` | `APP`=画面からの登録 / `MIGRATION`=2.0 からの移行 |

### 【書籍管理】（`views/reading/BookManagementView.vue`）

見出し・サマリ・分類タブ・棚の分け方は、**閲覧画面の【本棚】タブと同じ作法**にする
（2026-09-14 の指示。「本棚タブを参照して、タイトル・4 つのボタン・右上の冊数を合わせる」）。

```
本棚                                          [再読み込み] [＋ 新規登録]
  (すべて) (小説（5）) (雑誌・ガイド（1）) (未分類)   全 6 冊 ・ 読書中 6 冊 ・ 読了 0 冊
  置頂 2 冊 ───────────────────────────────────────────────
  ┌────────────────────────────┐ ┌────────────────────────────┐
  │ [表紙] 03.Harry Potter… [置頂]│ │ [表紙] Raya and the…  [置頂]│
  │  J. K. Rowling / Starter    │ │  難易度 / 英語 / 小説       │
  │  英語 / 小説 / 全 272 頁     │ │  タグ / PDF 未登録          │
  │  PDF 未登録（…Stone.pdf）    │ │  [⤓] [✎] [🔖] [🗑]          │
  └────────────────────────────┘ └────────────────────────────┘
  小説 3 冊 ───────────────────────────────────────────────
  （置頂に移した本は出さない）
  雑誌・ガイド 1 冊 ───────────────────────────────────────
```

- **1 行目は見出し `本棚` と操作**（`再読み込み` / `＋ 新規登録`）。
  **2 行目は分類とサマリ**: 左に分類のボタン、右端に冊数のサマリ
  **`全 N 冊 ・ 読書中 N 冊 ・ 読了 N 冊`**（API の `totals.bookCount / readingCount / finishedCount`。
  分類で絞っても全冊ぶんを出す）。2026-09-14 の指示で 2 行に分けた。
- **分類のボタンは閲覧画面の【本棚】タブと同じ丸いボタン**（`--radius-pill`・選択中は主色で塗る。
  設計システムの `.tabs` は使わない。利用者の指示）。
- **分類ボタン**（すべて／各分類（N）／未分類）。ボタンで `/books?categoryId=` を切り替える
  （未分類は `categoryId=0`）。タブは**実在する分類から自動で作る**（この画面に分類の管理ボタンは置かない）。
  分類を削除しても**本は消えず未分類に戻る**（`ON DELETE SET NULL`）。
- **置頂の本は「置頂」という別の棚に分けて最上部**に出す。その下に分類の表示順（未分類は最後）で並べ、
  置頂に移した本は分類の棚には**出さない**（同じ本が 2 回並ばないように）。
  **分類で絞ったときも同じ**（その分類のうち置頂の本を「置頂」の棚に分けて最上部に出す。
  置頂が 1 冊も無ければ棚は出さない）。2026-09-14 の指示。
  本が 0 冊の棚は見出しごと出さない（絞り込んだ棚だけは、置頂に移したぶんが全部でも見出しを残す）。
- 本棚カードの**表紙は 104×146**（2026-09-14 の指示で 76×106 から拡大。**閲覧画面の本棚カードも同じ寸法**）。
- 本棚カードは**本そのものの情報**だけ: 表紙・書籍名・作者・難易度・言語・分類・総ページ数・タグ・
  **PDF の状態**（実体があればファイル名だけ / 無ければ `PDF 未登録（元ファイル名）`）。
  **進捗バー・現在ページ・読書ステータス・読書時間・標記件数・最終読書日時は出さない**
  （冊数のサマリに「読書中・読了」が出るのは、棚のようすが一目で分かるようにするため）。
- 操作は**アイコンのみ**（文字を出さない）: **ダウンロード**（本文 PDF。`?download=true`）／修正／置頂／削除。
  **「この本を読む」は置かない**（読むのは書籍閲覧画面。役割を混ぜない）。
- 登録・修正は 1 つのダイアログ: 書籍名・作者・難易度・分類・タグ・概要・備考・置頂。
  本文 PDF と表紙のアップロード欄は**同じ行に左右**で並べる（2026-09-14 の指示。縦長にしない）。
  検証は PDF＝`.pdf`・200MB 以下、表紙＝画像（png/jpeg/webp）・5MB 以下。
- **総ページ数は入力させない**（2026-09-14 の指示で入力欄を廃止）。PDF を選ぶと pdf.js で数えて
  **`総ページ数 N 頁` を主色のチップで出す**。ファイル名も**太字**で出し、いまの値が一目で分かるようにする。
  数えられないときだけ「数えられませんでした。」と案内する（PDF を選ばずに登録したときは 1 頁）。
- 修正のときは、**登録済みの表紙をダイアログに出す**（2026-09-14 の指示。選び直すとその画像に入れ替わる）。
- 削除は確認ダイアログ。読書記録・標記は `ON DELETE CASCADE`、**PDF・表紙の実体も消す**（legacy ルートは除く）。

### 【書籍閲覧】（`views/reading/BookReaderView.vue`）

```
本棚                                  [分類: すべて|英語 小説|…]
┌──────────┐ ┌──────────┐ ┌──────────┐
│ [表紙]   │ │ [表紙]   │ │ [表紙]   │   ← 分類ごとの棚。カードに進捗・最終読書・標記数を出す
│ 書名     │ │ 書名     │ │ 書名     │
│ 読書中 3%│ │ 読了     │ │ PDF 未登録│
│ [読む]   │ │ [読む]   │ │ [読む]   │
└──────────┘ └──────────┘ └──────────┘
読書履歴（全体・新しい順）  日時 | 書籍 | ページ | 時間 | メモ | 削除

──────────────── 本を開いたとき（?bookId=） ────────────────
[← 本棚へ] 01.Harry Potter…  [読書記録]
┌──────┬───────────────────────────────────┬──────────────────┐
│ページ │ 本文（pdf.js の canvas）           │ 標記              │
│ 41   │  ┌─────────────────────────────┐  │ 語彙 818件        │
│ 42 ●8│  │  （ページを描画・標記を重ねる）│  │ ハイライト 9件    │
│ 43 ●3│  └─────────────────────────────┘  │ メモ 11件         │
│ …    │ [◀][42/272][▶] [−][＋][幅に合わせる]│ 一覧 → ページへ移動│
└──────┴───────────────────────────────────┴──────────────────┘
```

- **本文 PDF を pdf.js（同梱 `/lib/pdfjs/pdf.min.js` 3.11.174）で描画する**。2.0 と同じ:
  - `getDocument({ url: '/api/user/reading/books/{id}/pdf?v=版', withCredentials: true })`
  - canvas に `page.render(...)`（`devicePixelRatio` を考慮）、その上に
    `renderTextLayer(...)` のテキストレイヤー、さらに標記レイヤー（絶対配置の div）を重ねる
  - ページ送り（前/次・番号入力・ページレール）と拡大縮小（`−` / `＋` / 幅に合わせる）
  - **iframe / embed は使わない**（Spring Security が `X-Frame-Options: DENY` を返すため表示できない）
- 標記は**ページの上に重ねて表示**する。座標は `RED_標記情報` の正規化値（0〜1）をそのまま使う。
  2.0 が保存した `描画データ`（`{"kind":"selection","rects":[…],"note":…}`）があればその矩形を全部描き、
  無ければ `位置X/位置Y/幅/高さ` の 1 矩形で描く。
- 標記ツール: **語彙**（選択文字＋意味）・**ハイライト**・**下線**（本文を選択して付ける）・**メモ**。
  付けた矩形はページ内の正規化座標に変換して送る。付与・削除は標記レイヤーと一覧の両方からできる。
- **読書履歴**を出す: 本を開いているときは**この本の履歴**、本棚では**全体の履歴**。
  **本棚と読書履歴はタブで分ける**（資料管理の画面と同じ作法。`?view=history` と同期）。
  履歴には **読書日（From / To）とページ番号の絞り込み**と**1 ページの件数（20 / 50 / 100）**を置く。
  履歴の**削除は置かない**（利用者の指示。記録は消さずに残す）。
- 読書記録: この本の開始ページ・終了ページ（既定は今回読んだ範囲）・読書時間（分）・メモ。
  保存すると `RED_読書記録情報` に 1 行足し、`RED_書籍情報` の現在ページ・累計読書時間分・
  累計標記件数・最終読書日時・ステータスを同じトランザクションで更新する（既存ルール）。
- **【標記クリア】**（2026-09-14 の指示「標記だけでなく読書の進捗も消す」→ 続けて「読書記録も消す」）:
  図書館タブのカードのボタン。押すと確認のうえ、**その本の標記と読書記録（履歴）を全部削除**し、
  **あわせて読書の進捗を最初の状態に戻す**——
  `現在ページ`＝1・`読書ステータス`＝未着手・`最近の読書時間分`／`累計読書時間分`＝0・`最終読書日時`＝NULL・
  `累計標記件数`＝0（標記を消したあとに数え直す）。順番は
  **標記の削除 → 読書記録の削除 → 累計標記件数の数え直し → 進捗のリセット**で、
  すべて **1 つのトランザクション**（`ReadingServiceImpl#resetMarksAndProgress`）で行い、
  片方だけ残らないようにする。API は 2.0 の「標記削除」と同じ `DELETE /books/{bookId}/marks`
  （パスと返す形は変えない）。ボタンのラベルは【標記クリア】のままで、
  `title` に「標記・読書記録・進捗をリセットする」ことを出す。
  メッセージには消した件数を出す（例: `標記 3 件・読書記録 2 件と読書の進捗（現在ページ・ステータス）
  をリセットしました。`）。
  - **読書記録も消す**ので、リセット後の `累計読書時間分`／`最終読書日時` と残った記録が食い違うことはない
    （履歴（この本・全体）からその本の記録が消える）。
  - 進捗（％）は DB では `現在ページ / 総ページ` から導出するので、リセット後は 1 / 総ページ
    （例: 10 頁の本＝10%、2 頁の本＝50%）になる（DDL に `CHECK ("現在ページ" >= 1)` があるので
    0 ページにはできない）。ただし**画面には `読書ステータス` が「未着手」の本は 0% と表示する**
    （2026-09-14 の指示。現在ページは 1 のまま）。表示の規則は
    `features/reading/readingProgress.ts` の `displayReadPercent()` に集約し、
    【図書館】のカード・閲覧画面の【読書状況】・自分の本棚のホバー表紙パネル
    （`shelfLook#progressPercent` 経由）で同じ値を使う。
- **PDF 未登録の本**を開いたときは、はっきり「PDF 未登録」と出し、**2.0 の元ファイル名**を添えて
  「保護者が書籍管理画面から PDF をアップロードすると読めます」と案内する（§4）。
- 権限は**当面ロールで分けない**（家族共有の本棚。TODO と同じ。`docs/SECURITY_AND_ROLES.md`）。
  画面の想定利用者（保護者／生徒）はメニューでは分けていない。

### 【書籍閲覧2】（`views/reading/BookShelfView.vue`）

利用者の指示「実際の本の棚を探すような操作感と演出」で足した 3 つ目の画面（`/{area}/reading-shelf`）。
**既存の【書籍閲覧】はそのまま残す**（＝バックアップ。壊さない）。

- 本は**背表紙**として棚に並ぶ。幅・高さ・色は書名から決定的に決める（同じ本はいつも同じ見た目）。
  書名は縦書き（`writing-mode: vertical-rl`）。PDF 未登録の本は色を淡くして印を付ける。
- 演出: 棚に**左から順に並ぶ**／ホバーで**手前に出る**（表紙 240×330 の拡大＋ツールチップに
  書名・作者・難易度・言語・進捗）／クリックで**棚から抜き出され**、表紙が中央へ飛び込んでから本文 PDF になる。
  **`prefers-reduced-motion: reduce` のときは演出を付けない**（アクセシビリティ）。
- 棚は**木**に見せる（奥板・棚板・左右の側板）。`tokens.css` に木の色が無いので、
  茶の素（`--warning-600`）に赤み（`--danger-600`）を足した芯を、面の色（`--color-surface`）で
  薄めて使う（生の色は書かない＝明色・暗色どちらのテーマでも同じ作り方で木の濃さになる）。
  木目は**間隔を不揃い**にした繰り返しグラデーション、節は `radial-gradient` の楕円、
  奥行きは上下・左右の内側の影で出す（2026-09-14「もっと木らしく」の指示で作り直した）。
- 読み・標記・記録は既存の【書籍閲覧】と同じ API・同じ座標（正規化 0〜1）を使う。
- **閲覧（本を開いたとき）**は 2 カラム: **左＝本文 PDF（1fr）｜右＝【読書状況】・【ページ一覧】・
  【標記の一覧】（320px）**。2026-09-14 の指示の積み重ねで、いまは次の形:
  ① カード（【読書状況】・【ページ一覧】・【標記の一覧】）は**右カラム**に置く
     （一度左カラムへ移したが、「本文を広く・カードは右」の指示で右へ戻した。ページ一覧の順は
     読書状況 → ページ一覧 → 標記の一覧）。グリッドは `.rrd-reader` の
     `grid-template-columns: minmax(0, 1fr) 320px`、DOM の順も本文 → カードに合わせる。
  ② 画面の**見出し行（本棚へ戻る・書名）を廃止**して書名・作者・難易度・言語・読書ステータスを
     【読書状況】のカードの先頭にまとめ、【本棚へ戻る】は**本文ツールバーの【前へ】の左**へ、
  ③ 標記ツールは**本文の枠に貼り付けて常に見える**（`position: fixed` の入れ物
     `.rrd-tools-anchor` に置き、`scroll`／`resize` のたびに `placeTools()` が
     「ウィンドウの左上 + 8px」を基本に **本文の枠の見えている範囲**へ挟む。
     枠が画面から出ていくと一緒に隠れ、ほかのカードの上には出ない。ページの高さは消費しない）。
  ④ 【ページ一覧】のカードは**既定は閉じたまま**（【開く】でカードの中に一覧を出す）。カードに
     マウスを乗せた（またはキーボードで入った）ときは、**レイアウトを動かさない「悬浮式」の一覧**を
     本文の上へ左向き（`right: calc(100% + var(--sp-3))`・幅 30rem・`max-height: 70vh`）に開き、
     見出し（P.現在/総ページ）・凡例（既読／未読／標記あり）・ページのマス（`auto-fill`・40px 以上。
     現在ページはハイライト、標記のあるページは点）を出す。マスを押すとそのページへ移動し、
     マウスが外れたら 200ms 後に閉じる（一覧へ移って選べるように）。
  ⑤ 標記の入力の小窓（語彙・読み方・メモ）と既存の標記のポップアップは、文字をひと回り大きくして
     読みやすくする（`--fs-sm`／`--fs-md` を使う）。中国語の本の「読み方」は**ピンインを主役**にし、
     他の項目より大きい `--fs-2xl`・`--color-primary` のチップで出す。

### API（`/api/user/reading`。user-api の `ReadingController`）

2.0 の `api/englishreading/*` を 2.1 の作法（`ApiResponse` の封筒・認証はセッション・

業務ルール（2.0 から引き継いだもの）:

- 並びは **置頂 → 最後に読んだ順**（2.0 と同じ）。
- 読書記録を付けると **現在ページ・読書ステータス（総ページに達したら 読了）・
  最近の読書時間・累計読書時間（加算）・最終読書日時** をまとめて更新する。
- **累計標記件数** は標記の追加・削除のたびに数え直す。
- **標記を全部消すときは、読書の進捗と読書記録も一緒に消す**（【標記クリア】。標記の削除・
  読書記録の削除・進捗のリセットは同じトランザクション。記録も消すので、累計時間・最終読書日時と
  残った記録が食い違うことはない）。
- 読書履歴を消したら、残った記録から 最近/累計の読書時間と最終読書日時を計算し直す。
- **公開範囲（全体書籍 / 家庭の本）を必ず通す**。管理者＝`GLOBAL` だけ／保護者＝`GLOBAL`＋自家庭の
  `FAMILY`／生徒＝同じ可见範囲を読むだけ。登録・修正・削除は管理者＝`GLOBAL`、保護者＝自家庭の
  `FAMILY` だけ（生徒は不可）。**見えない本は 404（存在を漏らさない）、見えるが操作できないときは 403**。
- **【自分の本棚】はアカウントごと**（`RED_自分の本棚情報`）。【図書館】から入れて外す。
  初期状態は空（移行で一括投入しない）。入れる・外すは**冪等**で、触るのは呼び出した本人の行だけ。
- 分類の名前は**家庭の中で一意**（全体の分類は `所有家族学生ID IS NULL` のグループ）。
  同じ名前でも「全体の分類」と「家庭の分類」は別物として作れる。前後空白は落とす。

## 4. 本文 PDF と表紙の扱い（2026-09-13 に方針変更）

**最初の実装では「本文 PDF を持たない」と決めていた**（閲覧画面をページ番号中心の
ワークスペースにし、PDF の配信・マウントを避ける）。その理由は、当時
「閲覧の価値の中心はページごとの語彙・標記・メモ・記録で、PDF が無くても成立する」と考えたため。

しかし利用者から **「2.0 と同じように PDF を正しく表示して読めること」** という指示があり、
方針を変えた。現在は次のとおり:

| 項目 | 内容 |
|---|---|
| 保存 | `RED_書籍ファイル情報`（1 冊 1 PDF・1 表紙）＋実体は `study21.reading.storage-root`（既定 `${user.dir}/data/reading`、コンテナ `/app/data/reading`）配下の `books/<書籍番号>/` |
| 配信 | `GET /books/{id}/pdf`（`application/pdf`・inline・**Range 対応**）。表紙は `GET /books/{id}/cover` |
| 表示 | 同梱の pdf.js 3.11.174（`frontend/pc-web/public/lib/pdfjs/`）で canvas に描画し、テキストレイヤーと標記レイヤーを重ねる |
| 標記の座標 | `RED_標記情報` の `位置X/位置Y/幅/高さ`（正規化 0〜1）と `描画データ`（矩形の配列 JSON）を**そのまま使う**。移行済み 838 件はすべて値を持っているので、PDF を用意すれば 2.0 の標記がそのまま重なる |
| 上限 | PDF 200MB / 表紙 5MB（`application.yml` の multipart と、nginx の `client_max_body_size 210m`） |

### 2.0 の実体ファイルは未取得（重要）

2.0 は `COM_ファイル情報`（`機能区分='ENGLISH_READING'`）に 12 件（PDF 6・表紙 6）を持ち、
実体は **2.0 サーバの `webapps/file/ENGLISH_READING/<yyyyMM>/`** にあった。
この環境（2.0 のソース一式と DB のみ）からは**実体を取得できない**ため、移行では
**メタ情報だけ**を `RED_書籍ファイル情報` に引き継いでいる（`登録元コード='MIGRATION'`・
`保存パス='file/ENGLISH_READING/…'`・`保存ファイル名`＝2.0 の物理名・`ファイルサイズ`/`ページ数` は NULL）。

そのため移行した 6 冊は当面 **「PDF 未登録」** と表示される。読めるようにする方法は 2 つ:

1. **書籍管理画面からアップロードし直す**（同じ本に PDF を付ければ差し替えになる）
2. 2.0 の `file/ENGLISH_READING` ツリーを配備先の `files/legacy-reading/` にコピーし、
   `study21.reading.legacy-storage-root`（compose では `STUDY2_READING_STORAGE_ROOT=/app/data/legacy-reading`）
   を向ける。`保存パス` が `file/` で始まる行はこのルートから**読取専用**で解決される（2.1 からは消さない）

画面は「PDF 未登録（<2.0 の元ファイル名>）」と出すので、どのファイルを持ってくればよいか分かる。

なお `RED_書籍情報.総ページ数` は 2.0 の値（272〜1515）を引き継いでおり、
アップロード時には画面が pdf.js で数えたページ数で更新する。

### 実装メモ（同じ穴に落ちないために）

- **pdf.js は同梱**（`frontend/pc-web/public/lib/pdfjs/`。版 3.11.174、Apache-2.0。2.0 の
  `webapp/lib/pdfjs` と同じファイル）。CDN を使わないので閉域でも読める。
  worker は `pdfjsLib.GlobalWorkerOptions.workerSrc = '/lib/pdfjs/pdf.worker.min.js'` で明示する。
- **`pdfDoc` と `pageViewport` は `shallowRef` で持つ。** `ref()` にすると Vue の深い反応性が
  pdf.js のオブジェクトを Proxy で包み、pdf.js 内部の私的フィールド（`#d` など）が読めず
  `Cannot read private member #d from an object whose class did not declare it` で
  **PDF が 1 枚も描画されない**（実機の E2E で発見。単体テストもこれを再現する形にしてある）。
- **iframe / embed での PDF 表示は使えない**（Spring Security が `X-Frame-Options: DENY` を返す）。
  canvas に描画する pdf.js 方式なら問題ない。
- 配信は **Range 対応**が必須（pdf.js は分割取得する）。`Content-Type: application/pdf` を固定した
  状態で Spring の `ResourceRegion` を返すと 206 が 500 になるため、`HttpServletResponse` に
  `StreamUtils.copyRange` で書いている（バックエンドの実装メモ）。

### 値の対応で迷った点と、そう決めた理由

| 項目 | 決めたこと | 理由 |
|---|---|---|
| `登録ID` / `更新ID` → アカウントID | **NULL**（実データは全件 `'english_reading'`） | 人が実行した記録ではなく画面・機能の名前なので、対応表（`'liu'`→1 / `'ljz'`→2。TODO・日報と同じ判断）では引けない。**行は捨てずに NULL のまま残す**（2.0 の値は `書籍番号` 側に痕跡が残る） |
| `タグ` の空文字 | `NULL` に寄せる | 2.1 は「未設定は NULL」。実データ 6 冊では NULL のみだが、2.0 は空文字もありうる |
| `登録日時`/`更新日時`（書籍）が NULL | `最終読書日時` → `CURRENT_TIMESTAMP` の順で埋める | 2.1 は NOT NULL。2.0 の実データは 6 冊とも 登録日時 が入っていたので**このフォールバックは使われていない**（`最終読書日時` が NULL の 3 冊も `登録日時` をそのまま引き継いでいる） |
| 記録・標記の `登録日時`/`更新日時` | 移行時刻（`CURRENT_TIMESTAMP`） | 業務日時は `読書日時`・`ページ番号` が持っている。2.0 の値は一括投入時刻で、2.1 の監査列の意味（この行をいつ作ったか）に合わない |
| 標記の `太さ` | 全件 NULL のまま | 2.0 の既定は 1 だが実データに値が無い。勝手に 1 を入れず、2.1 のデータを正直に保つ |
| `書籍ID` → `書籍番号` | 2.0 の `書籍ID` をそのまま `書籍番号` に入れる | 利用者に見せている番号（`ER-yyyyMMdd-HHmmss`）で、既存の URL・メモと突き合わせられる |
| `現在ページ <= 総ページ数` の CHECK | 2.1 では外した | 2.0 のデータは満たしているが、ページ数を後から訂正すると既存行が弾かれるため。丸めはサービス側で行う |
