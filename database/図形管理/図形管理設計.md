## 1. 2.0 との対応

### 画面

| 2.0 | 役割 | 2.1 |
|---|---|---|
| `geometry.jsp`（＋`css/geometry.css`） | **図形一覧・検索**。キーワード（図形名・メモ・タグ）／種類／タグチップ／並び替えで絞り込み、カード（サムネイル・図形名・タグ・メモ・更新日時）を並べる。**新規作成・編集・コピー・削除**、サムネイルの拡大表示 | **【図形管理】** `/{area}/geometry`（§3） |

### API

| 2.0（`/api/geometry`） | 内容 | 2.1（`/api/user/geometry`） |
|---|---|---|
| `POST /search` | 一覧（`subject` / `kind` / `figureType` / `keyword` / `tag` / `sort` / `limit`） | `GET /figures`（`keyword` / `figureType` / `tag` / `sort` / `includeDeleted` / `page` / `size`。`totals` 付き） |
| `POST /get` | 1 件（`geometryId`） | `GET /figures/{figureId}`（`GeoGebraXML` とサムネイルつき） |

## 2. テーブル設計

### `GEO_図形情報`（作図 1 件 = 1 行）

| 列 | 型 | 意味 |
|---|---|---|
| `図形ID` | BIGSERIAL PK | 2.1 の内部 ID。API はこの ID で 1 件を引く |
| `図形番号` | VARCHAR(30) UNIQUE | 利用者に見せる番号。2.0 の `図形ID`（`GEO202604250005247792940` / `geometry-demo-1`）をそのまま引き継ぐ |
| `教科` | VARCHAR(20) | 現時点では `'数学'` 固定（2.0 と同じ） |
| `図形種別` | VARCHAR(20) | `geometry`=幾何図形 / `function`=関数グラフ |
| `登録区分` | VARCHAR(10) | `demo`=初期データ（サンプル）/ `saved`=利用者が作図したもの |
| `図形名` | VARCHAR(120) | 一覧・作図画面に表示する名称（2.0 の既定は `名称未設定`） |
| `メモ` | TEXT | 作図のポイント（未設定は NULL） |
| `タグ` | TEXT | **`|` 区切り**（例 `三角形|部品`）。未設定は NULL |
| `GeoGebraXML` | TEXT NOT NULL DEFAULT '' | GeoGebra の作図データ（XML）。未作図は空文字 |
| `サムネイル画像` | TEXT | 一覧用サムネイル（**Base64 PNG のデータ URI**）。無い行は NULL |
| `表示順` | INTEGER NOT NULL DEFAULT 0 | 一覧の並び（2.0 は登録時に `MAX+1`。同値を許す） |
| `状態コード` | VARCHAR(20) | `ACTIVE`=有効 / `DELETED`=削除済（**論理削除**） |
| `バージョン` | INTEGER NOT NULL DEFAULT 1 | 楽観的ロック（作図画面からの更新で使う） |
| `登録者/更新者アカウントID` | BIGINT NULL | `ACC_アカウント` への FK（`ON DELETE RESTRICT`）。引けない 2.0 の ID は NULL |
| `登録元/更新元コード` | VARCHAR(20) | `APP`=画面 / `MIGRATION`=2.0 からの移行 |
| `登録日時` / `更新日時` | TIMESTAMP NOT NULL | |

- **持ち主は持たない（家族で共有する教材）。** 2.0 に持ち主の概念が無く、実際に 1 つの
  図形一覧を家族で使っていたため、`アカウントID` のような所有列は作らない。
  誰が作図・更新したかは `登録者/更新者アカウントID` に残す（読書管理・TODO と同じ判断）。
- 制約: `図形種別`・`登録区分`・`状態コード` の CHECK、`表示順 >= 0`、`バージョン >= 1`、
  登録者/更新者は `ACC_アカウント` への FK（`ON DELETE RESTRICT`）。
  2.0 にあった `図形名 NOT NULL`・`GeoGebraXML NOT NULL`・`登録区分`・`削除FLG` の CHECK は
  そのまま引き継いでいる（`削除FLG` は `状態コード` に読み替え）。
- 索引:
  - `図形番号` UNIQUE（`uq_geo_figure_no`）
  - 一覧の絞り込み `教科, 状態コード, 登録区分, 更新日時 DESC`（`idx_geo_figure_search`。
    2.0 の `IDX_TRN_図形作成情報_検索` の `削除FLG` を `状態コード` に置き換えただけ）
  - 名称検索 `教科, 図形名`（`idx_geo_figure_name`。2.0 の `IDX_TRN_図形作成情報_名称` と同じ）
  - 表示順の並び `教科, 表示順, 図形ID`（`idx_geo_figure_order`。同上）
  - タグ `タグ`（`idx_geo_figure_tag`。同上。**2.0 と同じ素の btree で、部分一致には効かない**。
    実際のタグ検索は `ILIKE '%タグ%'` なので、効かせるなら `pg_trgm` か配列型への変更が要る。§5）

### 設計の判断と、そう決めた理由

| 論点 | 決めたこと | 理由 |
|---|---|---|
| サムネイルの置き場所 | **Base64 で DB に持つ**（2.0 と同じ。別テーブル・ファイル分離をしない） | ①件数が 100 件程度で、合計しても数十MB なので DB で扱える規模。②2.0 が同じ持ち方なので**移行で変換が要らない**。③一覧のカードは `GET /figures/{figureId}/thumbnail` が Base64 を PNG に戻して返すだけになり、ファイル実体の配置・配信・バックアップを考えなくてよい（配備はコンテナなので、マウントを増やさずに済む）。④`サムネイル画像 IS NOT NULL` で「サムネイルの有無」がそのまま判定できる。 |
| タグの区切り文字 | **`|` 区切り（カンマではない）** | 2.0 は `String.join("|", tags)` で保存し、検索・タグ候補も `|` で分解していた。実データ 100 件（タグあり）も**すべて `|`**。カンマへ変えると 2.0 と突き合わせられなくなり、移行で変換が必要になるだけで得がない。2.1 の API・画面も `TAG_SEPARATOR = '|'` で揃えてある。 |
| `削除FLG` | **`状態コード`（`ACTIVE` / `DELETED`）に置き換えた。論理削除は残す** | 2.0 の削除は `DELETE` ではなく `UPDATE … SET 削除FLG='1'` で、消した図形も一覧の絞り込みから外れるだけだった（サムネイルもデータも残る）。2.1 も**同じ論理削除**を保つ。列名と値域を 2.1 の規約（`状態コード` ＋ CHECK）に合わせ、`'0'/'1'` のような意味の分かりにくい値を使わない。 |
| 知識点との紐づけ（`TRN_知識点情報.図形ID一覧`） | **移行しない** | 2.0 は知識点 77 件のうち **46 件**に `図形ID一覧`（`GEO…|GEO…` の `|` 区切り、86 参照・84 図形）を持っており、**知識点 → 図形**の参照がある。ただし **2.1 にはまだ知識点テーブルが無い**（知識点管理は未実装）ので、受け皿が無い。無理に `GEO_図形情報` 側へ列を足すと「1 図形 = 1 知識点」しか持てず、多対多を壊す。知識点テーブルができた時点で、**`図形番号` で読み替える中間テーブル**（例 `MTH_知識点図形情報`）を作って 2.0 から移行する（§5）。 |
| `function`（関数グラフ） | 列と UI は用意するが、**実データは 0 件** | 2.0 の作図画面は種類で `appName` を `geometry` / `graphing` に切り替えており、`011_…sql` で `図形種別` を足した形跡がある。ただし実データは全件 `geometry`。列と CHECK は用意して将来に備え、**移行では触らない**。 |

### 2.0 から変えた点

| # | 2.0 | 2.1 | 理由 |
|---|---|---|---|
| 1 | 主キーが業務キー（`図形ID='GEO…'`） | `図形ID` は BIGSERIAL、2.0 の ID は `図形番号` として残す | 2.1 の規約（内部 ID は BIGSERIAL、業務キーは別列） |
| 2 | `削除FLG` `'0'`/`'1'` | `状態コード` `ACTIVE`/`DELETED` | 値の意味を列名と CHECK で表す。論理削除という振る舞いは変えない |
| 3 | `登録ID` / `更新ID` は自由文字列（`'geometry.jsp'` / `'system'` / `'ljz'`） | `登録者/更新者アカウントID`（FK）＋ `登録元/更新元コード` | 2.1 の監査規約。画面・機能の名前は人ではないので NULL になる |
| 4 | 楽観的ロックなし（後勝ち） | `バージョン` | 作図画面は XML とサムネイルを丸ごと上書きするので、別の端末の更新を潰さないようにする |
| 5 | `図形ID` をアプリが採番（`GEO` ＋ 日時 ＋ ミリ秒 ＋ 連番） | 同じ。ただし重複時は 2.1 の API が採番し直す | `uq_geo_figure_no` で守る |
| 6 | タグ候補は `tagSuggestions` が毎回 `|` を分解して集計 | 同じ（`idx_geo_figure_tag` は 2.0 から引き継いだだけ） | 件数が 100 件規模なので集計は軽い |

| 列 | 値 |
|---|---|
| `教科` | `数学`（現時点では固定） |
| `図形種別` | `geometry`=幾何図形 / `function`=関数グラフ |
| `登録区分` | `demo`=初期データ / `saved`=利用者が作図したもの |

## 3. 2.1 の画面設計

親メニュー**【数学勉強】＞【図形管理】**の下に 2 つの画面を置く（左メニューの 2 階層）。

```
数学勉強
├ 知識点管理   /{area}/math-knowledge   … 未実装
├ 誤問題集     /{area}/math-wrong       … 未実装
└ 図形管理     /{area}/geometry         … 一覧・検索（＋作図画面 /{area}/geometry-draw）
```

2.0 の 2 画面（一覧と作図）の分け方をそのまま引き継ぐ。作図画面は 2.0 と同じく
**一覧から開く**（モーダルではなく別ルートにして、直接開く・再読み込み・戻るが効くようにする）。

### 【図形管理】＝一覧・検索

```
図形管理                                              [再読み込み] [＋ 新規作成]
  絞り込み: [キーワード（図形名・メモ・タグ）] [種類▾ すべて/幾何図形/関数グラフ] [並び替え▾]
  タグ: [三角形] [部品] [平行線] [平行四辺形] [円] …        （タグ候補。件数順）
  12 件 / 全 96 件
  ┌────────────────┐ ┌────────────────┐ ┌────────────────┐
  │ [サムネイル]    │ │ [サムネイル]    │ │ [サムネイル]    │
  │ 三角形部品      │ │ 弓形            │ │ 豚足型1         │
  │ [幾何図形][元]  │ │ [幾何図形][元]  │ │ [幾何図形][元]  │
  │ 三角形 部品     │ │ 円 扇形         │ │ 平行線          │
  │ 2026-04-25 更新 │ │ 2026-04-25 更新 │ │ 2026-04-25 更新 │
  │         [編集][コピー][削除]        │
  └────────────────┘ └────────────────┘ └────────────────┘
```

- 検索は 2.0 と同じ 4 つ（**キーワード・種類・タグ・並び替え**）。キーワードは
  **図形名・メモ・タグ**の部分一致、並び替えは `更新日が新しい順` / `作成日が新しい順` / `名前順`。
- カードは **サムネイル・図形名・種別バッジ（幾何図形 / 関数グラフ）・登録区分バッジ（元＝demo）・
  タグ・メモ・更新日時**。サムネイルが無い行（`demo` の 2 件）は 2.0 と同じく図形アイコンの
  プレースホルダを出す。
- 操作は **【新規作成】【編集】【コピー】【削除】**（2.0 の一覧のボタンと同じ）。
  編集・コピーは作図画面を開く。コピーは `POST /figures/{figureId}/copy` で
  **新しい `図形番号` を採番**して複製する（2.0 は一覧の JS が `save` を呼んでいた）。
- 削除は確認ダイアログ。**論理削除**（`状態コード='DELETED'`）で、行は残る。
  `includeDeleted` を付けた一覧では削除済みも見られる（`totals.deletedCount`）。
- 件数は API の `totals`（図形数・幾何・関数・削除済み）を出す。

### 【作図】＝GeoGebra

```
[← 一覧へ戻る]  図形作成                            [折りたたむ] [中央表示] [保存]
 ┌──────────────┬────────────────────────────────────────────────────────┐
 │ 種類 [幾何▾] │                                                        │
 │ 図形名 [三角形部品]                                                   │
 │ メモ   [作図のポイント]                                               │
 │ タグ   [三角形 ×][部品 ×] [+ 入力して Enter] 候補: [三角形][部品]      │
 │ コマンド [A = (0, 4)                    ]                            │
 ├──────────────────────────────────────────────────────────────────────┤
 │                    GeoGebra アプレット（幾何 / 関数）                  │
 └──────────────────────────────────────────────────────────────────────┘
```

- 種類が `geometry` なら `appName='geometry'`、`function` なら `'graphing'`（2.0 と同じ）。
  コマンド欄のプレースホルダも `A = (0, 4)` / `f(x)=x^2+1` で切り替える。
- 保存時に **`GeoGebraXML`（`getXML`）とサムネイル（`getPNGBase64(1.50, false)`）を同時に作る**
  （2.0 と同じ。サムネイルは `data:image/png;base64,…` のまま保存する）。
- 図形名が空なら `名称未設定` にする（2.0 の既定。実データにも `名称未設定`・`無題の図形` がある）。
- 更新は `version` を送り、**一致しなければ 409**（別の端末が先に保存していたら、その旨を出して開き直す）。
- タグは `|` を入力させない（`TAG_SEPARATOR` を含むタグは 400）。2.0 と同じく候補から選べる。
- 表示順は登録時に `MAX(表示順)+1`（2.0 と同じ）。並べ替えは `PATCH /figures/{figureId}/order`。

### API（`/api/user/geometry`。user-api の `GeometryController`）

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/figures` | 一覧（`keyword` / `figureType` / `tag` / `sort` / `includeDeleted` / `page` / `size`）。`totals` 付き |
| GET | `/figures/{figureId}` | 1 件（`GeoGebraXML` とサムネイルつき。作図画面用） |
| GET | `/figures/{figureId}/thumbnail` | サムネイルの PNG（Base64 を復号して返す。10 分キャッシュ） |
| POST | `/figures` | 登録（`図形番号` を採番。`登録区分='saved'`） |
| PUT | `/figures/{figureId}` | 更新（`version` が一致するときだけ。違えば 409） |
| POST | `/figures/{figureId}/copy` | コピー（新しい `図形番号` で複製。図形名に ` のコピー` を付ける） |
| PATCH | `/figures/{figureId}/order` | 表示順の変更 |
| DELETE | `/figures/{figureId}` | 削除（`状態コード='DELETED'` の論理削除） |
| GET | `/tags` | タグの候補（`|` 区切りを分解して件数順・最大 50 件） |

業務ルール（2.0 から引き継いだもの）:

- 一覧の既定は **更新日の新しい順**。`ACTIVE` だけを出す（`includeDeleted=true` で削除済みも）。
- 図形は**家族で共有**（2.0 に持ち主の概念が無いため）。登録・更新した人は監査列に残す。
- タグは `|` 区切りで保存し、候補は**分解して件数順**に出す（2.0 の `tagSuggestions` と同じ）。
- サムネイルは**保存時に作る**。XML から後で作り直す仕組みは 2.0 にも無い（§5）。
- 権限は**当面ロールで分けない**（家族共有の教材。TODO・読書管理と同じ。
  `docs/PERMISSION_MATRIX.md` は「数学勉強 ＞ 図形管理: 作成・閲覧」で試作扱い）。

### 値の対応で迷った点と、そう決めた理由

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 期待件数（ACTIVE / DELETED） | **96 / 6**（当初の作業指示は「ACTIVE 100 / DELETED 2」） | 指示の値が古く、実測では `削除FLG='1'` が **6 件**（demo 2 件＋saved 4 件）だった。指示値を検証条件に書くと移行が必ず失敗するので、**実測値**で判定し、検証 DO ブロックのコメントにも差分を残した。 |

| `タグ` の変換 | **変換しない**（`|` 区切りのまま） | 2.1 の規約をカンマにすると 100 件すべてを書き換えることになり、2.0 との突き合わせもできなくなる。2.1 の API・画面も `|` に合わせてある。 |
| `メモ`・`タグ` の空文字 | NULL に寄せる | 2.1 は「未設定は NULL」。実データに空文字は無い（NULL のみ）が、2.0 は空文字もありうる。 |
