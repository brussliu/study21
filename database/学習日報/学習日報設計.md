## 1. 画面の考え方（2.0 との違い）

| | 2.0（daily_report.jsp） | 2.1（作り直し） |
|---|---|---|
| 主役 | 当日の入力フォーム（週ストリップは補助） | **月カレンダー**（記録の入力と提出もカレンダーから） |
| 「いつ書いたか」 | 週ストリップのみ | **月カレンダーで一目**。提出済＝緑 / 記載あり（未提出）＝黄 / 未提出＝グレー / 祝日・休日＝淡い赤のバッジ |
| マスの情報 | 日付だけ | 未展開でも **提出状態・時限数・掌握度の平均・ノート数・その日の教科（全部）・振り返り・今夜の勉強内容** |
| 展開したとき | （行の下に週ストリップ） | **その行のマスが縦に伸びて**、授業ごとに 時限・教科（色）・授業内容・掌握度・ノート、さらに 4 観点・振り返り・宿題 |
| 時間割 | マスタ無し・当日入力のみ | **記録から推定**（曜日×時限で最も多い教科。推定のマスは破線で「推定」と表示） |
| 記入 | 1 件ずつ | **授業のマスを押して入力**＋カレンダー下の【＋ 記録を追加】（空いている時限を初期値に） |
| 提出 | 概念が無い（日報がある＝提出した） | **【提出】で提出済**。保存しただけは「記載あり」。提出後に編集すると**再提出待ち**に戻る |

    [数学][国語][英語][理科][社会][体育]                     [＋ 記録を追加] [提出]

### カレンダーのマスの決めごと（未展開）

- **日曜の列は狭くする**（日曜は授業が無いため。`grid-template-columns: repeat(6, minmax(0,1fr)) minmax(0,0.34fr)`）。
  空いた幅は月〜土の 6 日に自動で配分される（実測: 月〜土 211px / 日 72px）。
- **教科は記録したぶんを全部出す**（`+n` で省略しない）。折り返して並ぶので、マスの高さは中身に合わせて伸びる。
- **どの教科にも色を付ける**（ユーザーの指定）:
  - 色は 10 分類（英語 / 国語 / 数学 / 理科 / 社会 / 音楽 / 美術 / 体育 / 技術・家庭 / その他）。
    `features/daily-report/subjectColors.ts` の `subjectTone()` が教科名から決める
    （表記ゆれも同じ色にまとめる: 「現代文」→国語、「化学」→理科、「保健体育」→体育 など）
  - 色は `tokens.css` の変数だけを使う（`--subject-english/japanese/math/science` と、
    用途が近い既有の変数 `--warning-600` / `--primary-600` / `--danger-600` /
    `--accent-500` / `--info-600` / `--neutral-500`）。教科クラスは 2 つの変数を出す:
    `--dr-subject-tone`（帯と教科名の色）と `--dr-subject-soft`（下地。`color-mix` で 14% 薄くした色）
  - **理科（化学・物理・生物など）は緑を使わない**（`--subject-science: #0b7285` の青緑）。
    提出済みの日のマスは薄い緑（`--color-success-soft`）なので、緑のままだと
    カードの下地と教科色が背景に溶けて読めなくなるため（ユーザーの指定で変更）
- **授業カードは 4 つの状態を別の手がかりで示す**（ユーザーの指定で作り直した）:

  | 状態 | 下地 | 左帯 | 線 | 教科名 |
  |---|---|---|---|---|
  | 主科（記録済み） | **教科色を 14% 薄く敷く** | 太い（4px） | 実線 | 教科色・太字 |
  | 副科（記録済み） | 白地（敷かない） | 細い（3px） | 実線 | 教科色 |
  | 推定（未記録） | **斜線（ハッチ）の灰色** | 細い（3px） | **破線**（灰色） | 灰色（教科色を使わない） |
  | 空き（削除した時限） | なし | **なし** | 破線 | 期間だけ薄く表示 |

  つまり **下地の有無＝主科かどうか**、**線が実線か破線か＝記録済みかどうか**で読み分ける。
- **チップ（未展開のマス・凡例・ダイアログ）は主科と副科で見せ方を分ける**（ユーザーの指定）:
  - 主科 … 教科色の文字＋薄い下地（実線）
  - 副科 … **灰色の文字＋灰色の破線**（`--neutral-400` の文字・`--neutral-300` の枠。下地なし）
  - 未展開のマスは狭いので、副科は色を使わず目立たせない
    （展開したカードは副科も教科色の帯を使う。詳細を見るときは見分けたいため）
- カードの見せ方の凡例は「見出し：**展開したカード**」＋「主科 / 副科 / 推定 / 空き」の 4 つの見本を出す
  （`.dr-card-legend`）。未展開のマスに出る**教科チップ**（上の凡例）とは別物なので見出しで区別する。
  見本の帯の色は分類に合わせる（主科＝数学の紫 / 副科＝体育のネイビー。以前は副科も数学の紫だった）。
- 展開したマスの**授業カードは高さを固定する**（`height: 4.5rem`）。
  記録済み（提出済）の日と推定（未提出）の日で **1 枚ずつの高さが完全に一致する**ようにするため、
  中身は 1 行ずつ省略表示（`white-space: nowrap` + `text-overflow: ellipsis`）にし、
  推定の案内も「推定：押すと記録できます」の 1 行に短くしている
  （ノートの情報が無いカードにも同じ高さの行を確保する）。
- 掌握度は**星**で出す（`stars()`。3 → ★★★☆☆）。編集ダイアログの入力も**星を押して選ぶ**。
- 教科の凡例は「主科（5 教科・下地あり）」と「副科（5 分類・下地なし）」を並べ、どちらも教科ごとの色で出す。
  カードの見せ方の凡例（主科 / 副科 / 推定 / 空き）も下に出す。
- 実装: `features/daily-report/subjectColors.ts`（`isMainSubject` / `subjectClass`）と
  `features/daily-report/daily-report.css`（`.dr-subject--*` / `.dr-chip.dr-subject--minor`）。

## 1.1 授業と 1 日のまとめ（2026-09-12 追加）

授業の属性は次の 9 項目（ユーザーの指定）。振り返り・宿題は「1 日のまとめ」に分けた。

| # | 項目 | 保存先 |
|---|---|---|
| ① | 時限（**最大 10 限**） | `TRN_学習日報授業情報.時限` |
| ② | 教科 | `教科名`（主科＝英語・国語・数学・理科・社会 / 副科＝それ以外） |
| ③ | 掌握度（1〜5・**星で入力**） | `掌握度`。展開したマスでも星で表示（3 → ★★★☆☆） |
| ④ | 授業内容 | `授業内容` |
| ⑤ | ノート記録（**主科だけ**・ラジオ） | `ノート記録フラグ`。副科は常に「記録しない」 |
| ⑥ | ノート記載しない理由（⑤で「記録しない」を選んだときだけ） | `ノート記載しない理由`（自由入力＋候補ボタン） |
| ⑦ | 学習集中度（1〜5・**星で入力**） | `学習集中度`（**授業ごと**。2026-09-12 に日報から移した） |
| ⑧ | 学習量（1〜5・**星で入力**） | `学習量`（同上） |
| ⑨ | 学習態度（1〜5・**星で入力**） | `学習態度`（同上） |

- **時限の選択肢はその日の日報に合わせる**（`periodOptions`）: 出すのは
  「いま編集中の時限」＋「その日でまだ記録が無い時限」で、**最大 10 限**まで。
  記録済みの時限は選択肢に出さない（選ぶと別の授業を上書きしてしまうため）。
  例: 1〜6 限が記録済みの日で 1 限を開くと `1 / 7 / 8 / 9 / 10 限`（既定は 1 限）。
  【授業追加】では空いている時限だけが出て、既定は最初の空き時限。
  推定（未記録）の時限は上書きにならないので、選択肢からは外さない。
- **掌握度・学習集中度・学習量・学習態度は星で入力する**（`components/ui/StarRating.vue`）。
  星を押すとその値になり、**同じ星をもう一度押すと未入力に戻る**。
  マウスを重ねているあいだはその値をプレビューする。星は `button` なのでキーボードでも選べる
  （セレクトではない）。値は表示にも使う（`stars()`）。

- 日報側の 4 観点（`学習集中度`・`理解度`・`学習量`・`学習態度`）は**使わない**
  （2.0 から移行した値を残すため列だけは持っている。画面には出さない）。
- **1 日のまとめ**（`POST /daily-reports/day`）の項目は 3 つ: **祝日/休日区分**（通常・祝日・休日）／
  **今日の振り返り**／**今夜の勉強内容**。
- **祝日・休日にすると、その日の授業の記録は全部消える**（時間割ごと休みにする）。
  その日は「未提出」に数えず、**提出率の分母（平日の数）からも外す**（`restDays`）。
  祝日・休日の日に授業を追加すると、その日は「通常」に戻る。
- **祝日・休日も「0限」と出し、【提出】できる**（ユーザーの指定。2026-09-12 に変更）:
  - マスの 1 行目は `0限`（授業が無いことを件数で示す。掌握度・ノート数は出さない）
  - 提出は **0 限のまま**できる（`submit` は記録が 0 件でも、祝日・休日なら通す）。
    確認ダイアログは「祝日として日報を提出します（授業の記録はありません）。」と案内する
  - 提出してもバッジは**祝日・休日のまま**（日そのものが祝日なので種類を消さない）。
    提出済かどうかは【提出済み】ボタンと**マスの背景色**で分かる
  - **提出した祝日・休日は背景を淡い赤**（`--color-danger-soft`）にする。
    平日の提出済みは緑（`--color-success-soft`）なので、祝日は日そのものの色（赤系）のまま
    「提出した」ことも示す。枠は破線のまま（祝日・休日の印）。
    提出前は背景を変えない（`transparent` のまま）
  - 提出率の分母から外す扱いは変えない（祝日に提出しても提出率は動かない）
- 画面の操作はすべて**展開したマスの中**にある（ページの一番下には置かない）:
  **【授業追加】【当日まとめ】【提出】**（前の 2 つは同じ幅にする）。
- **授業カードの削除**: 記録済みのカードにはゴミ箱アイコンがあり、1 限ぶんだけ消せる
  （`DELETE /daily-reports/lesson?date=&period=`）。消した時限は**詰めない**（1 限を消しても 2〜6 限のまま）。
  提出済の日を消したときは、編集と同じく下書き（再提出待ち）に戻る。
- **消した時限の枠は残す**: 展開したマスは 1 限から**その日の最後の時限**までを必ず並べる
  （`lessonSlots()`）。記録が無い時限は、提出前なら**推定の枠**（「推定：押すと記録できます」）、
  推定も無ければ破線の「n限 空き」になる。どちらも高さは他のカードと同じ 72px で、
  **下のカードは上に詰まらない**（消した時限がどの時限か分かるようにするため）。

## 1.2 土日と日曜列の幅（2026-09-12 追加）

- **土日も平日とまったく同じ扱い**にする（土日にも授業があるため）。週表示はいつも 7 日ぶん返し、
  記録が無い日は「**未提出**」と表示して、【授業追加】【当日まとめ】も普通に押せる
  （「授業なし」とは出さない）。推定の時間割があれば同じように埋める。
- **祝日・休日にした日だけは授業が無い日**として扱う（推定もしない・未提出にも数えない）。
- **推定の枠は「提出前」だけ出す**（`week()`）:
  - 記録が無い日（未提出）… 推定だけ
  - 記録があるが**まだ提出していない**日（記載あり・再提出待ち）… **記録した時限＋まだ記録していない時限の推定**を
    時限順に混ぜて出す。1 限だけ記録した日に 2〜6 限の枠が消えると、続けて入力できなくなるため
  - **提出済み**の日 … 提出した記録だけ（推定は混ぜない）
  - 1 件も推定が無い時限（推定の材料が無い）は、破線の「n限 空き」の枠にして**位置を保つ**
- **細い列（日曜）では操作ボタンを縦に並べる**（ユーザーの指定）:
  展開したマスの下の【授業追加】【当日まとめ】は、幅があるときは 1 行に同じ幅で並べる。
  日曜のように列が細いとき（マスの幅 130px 以下）は **1 つずつ縦に並べ**、
  アイコンを隠してラベルを折り返し、**文字が切れない**ようにする
  （マスの幅で切り替えるので、日曜に授業がある月のように 7 日とも同じ幅のときは 1 行のまま）。
  実装は `@container`（`.dr-day` をクエリコンテナにする）で `daily-report.css` に置いている。
- **左上の年月は「前の月」「次の月」のボタンの中央**に置く（`.dr-toolbar__month` は幅 9rem 固定＋中央寄せ）。
  月が変わって文字数が増えても（9月 → 10月）ボタンの位置が動かない。
- **未展開のマスにも振り返りと今夜の勉強内容を出す**（ユーザーの指定）:
  - 「全体の振り返り」は **2 行**、「今夜宿題内容」は **1 行**で省略する（`.dr-day__review` /
    `.dr-day__review--homework`）
  - 行の間隔は「限数・掌握度 → 教科チップ → まとめ」で少し広めに取る
    （`margin-top: 6px`。まとめの中の振り返りと今夜の勉強は 3px で詰める。ユーザーの指定）
  - **項目名は文字ではなくアイコン**で示す（振り返り＝`edit`（ペン）/ 今夜の勉強＝`moon`（月））。
    未展開のマスも展開したマスのまとめも同じアイコンにそろえる（ユーザーの指定）。
    読み上げ用の文字は `.visually-hidden` で残し、`title` にも項目名を入れる
  - そのために `status` API（`DayStatus`）にも `review` と `homework` を足した
  - マスの高さは **10.5rem**（以前は 8.5rem。2 行ぶん高くした）
  - 「内容 n 件」「ノートあり」は**出さない**（細かすぎるため。詳細は週を開いて見る）
- **カードの並びは日をまたいで揃える**: 記録が無い日（未提出）でも、週を開いていれば
  推定の時間割が分かるので、1 行目のサマリに **「n限 推定」** を出す。
  記録がある日は「n限 掌握 x.x」（＋ノート数）で、**行の高さは同じ**。
  この行の有無でカードの並びが 1 行ぶん上下にずれるため、出さないと未提出の日だけ
  カードが上にずれて見える（祝日・休日は授業が無い日なのでこの行も出さない）。
- **日曜の列の幅**: 当月に日曜の**記録**が無ければ日曜だけ狭く（他 6 日の約 34%）、
  1 日でもあれば **7 日とも同じ幅**にする（`.dr-calendar--all-equal`）。
- **カレンダーの凡例は 4 つ**: 提出済（緑）／記載あり（黄・未提出）／未提出（グレー）／祝日・休日（淡い赤）。
  土日も「未提出」と出すようになったので、「授業なし」の見本は凡例から外した。
- **当日のマスは暗紅色の枠**（`.dr-day--today` は `--danger-600` の 2px 枠）、
  **選択中のマスはテーマ色の枠**（`.dr-day--selected` は `--color-primary`）。
  以前は当日もテーマ色で、選択中と見分けが付かなかったため分けている。

## 1.3 提出（2026-09-12 追加）

2.0 は「日報の行がある＝提出した」という扱いだった。2.1 は **記載あり（DRAFT）** と
**提出済（SUBMITTED）** を分ける（ユーザーの指定）。

| 操作 | 状態 | カレンダーの色 |
|---|---|---|
| 記録を保存した（1 限ぶん／【＋ 記録を追加】） | `DRAFT`（記載あり） | 黄 |
| 【提出】を押した | `SUBMITTED`（提出済・提出日時を記録） | 緑 |
| 提出後に編集した | `DRAFT` に戻る（**再提出待ち**。提出日時は残す） | 黄（バッジは「再提出待ち」） |
| 記録が無い日（平日も土日も） | 行が無い | グレー（未提出） |
| 祝日・休日にする | `休日区分コード` を更新（授業は消え、未提出にも提出率の分母にも入らない） | 淡い赤のバッジ（未提出とは出さない）。0 限と出し、**そのまま提出できる**（提出後は背景も淡い赤） |

- 提出できるのは **記録が 1 件以上ある日**（授業が 0 件なら 400「記録が無い日は提出できません」）。
- すでに提出済みの日をもう一度提出すると 400（画面は【提出済み】で押せない）。
- **月の提出率は提出済の日だけで数える**（保存しただけの日は分子に入らない）。
- 2.0 から移行した 24 件と、追加前に作られていた行は提出済として扱う
  （`MIG_TRN_学習日報_提出_20260912.sql`。冪等）。

## 2. データ

- 1 日 = `TRN_学習日報情報` 1 行（対象日・振り返り・宿題・備考・
  `提出状態コード`（DRAFT / SUBMITTED）・`提出日時`・`休日区分コード`（NORMAL / HOLIDAY / REST））。
  4 観点（学習集中度・理解度・学習量・学習態度）の列は 2.0 からの移行データ用に残しているが、画面では使わない。
- 授業 = `TRN_学習日報授業情報`（時限・教科名・授業内容・掌握度・ノート記録フラグ・
  ノート記載しない理由・学習集中度・学習量・学習態度）。
- 科目 = `TRN_学習日報科目情報`（表示順・教科名・学習内容）。
- 持ち主は `アカウントID`（`ACC_アカウント` への FK）。2.0 から移行した分は
  `旧ユーザーID`（'ljz'）も残している。**時間割のマスタは持たない**（記録から推定する）。

## 3.5 LINE 通知（提出時に日報を送る）

2.0 は**日報の保存後**に LINE（Messaging API の push）へ送っていた。2.1 は**【提出】したときに送る**予定。
送信先も 2.0 はコードに直書きだったが、2.1 は**設定画面から変えられる**ようにする。

**2026-09-12 時点では設定の受け皿だけを用意した（送信処理は未実装）。**

### 設定（システム設定 →「学習日報」→「LINE通知」）

| 設定 | 設定キー | 型 | 既定 |
|---|---|---|---|
| 日報を LINE へ送る | `LINE_DAILY_REPORT_ENABLED` | true/false | `false` |
| 日報の送信先ID | `LINE_DAILY_REPORT_TO` | text | 空（空なら「デフォルト送信先ID」へ送る） |
| 再提出でも送る | `LINE_DAILY_REPORT_SEND_ON_RESUBMIT` | true/false | `false` |
| メッセージ本文のテンプレート | `LINE_DAILY_REPORT_TEMPLATE` | text（textarea） | 既定テンプレートを登録済み |
| 授業1件のテンプレート | `LINE_DAILY_REPORT_LESSON_TEMPLATE` | text（textarea） | 既定テンプレートを登録済み |

- 置き場所は「学習日報」のページ（ユーザーの指定。`LINE_DAILY_REPORT_*` のキーはそのまま）。
  送信に使う接続情報だけは「LINE連携」のページにある。
- **値をどこから持ってくるか**（2026-09-12 調査）:
  2.0 の設定 DB（study2 の `COM_設定情報`）では
  `LINE_MESSAGING_CHANNEL_ACCESS_TOKEN` と `LINE_MESSAGING_DEFAULT_TO` は**空**で、
  実際には `com.study2.line.service.LineMessageServiceImpl` の
  `FALLBACK_CHANNEL_ACCESS_TOKEN` / `FALLBACK_DEFAULT_TO`（＝コード内の直書き）が使われていた
  （`loadConfig()` が `firstNonBlank(設定値, フォールバック)` で解決している）。
  日報は 2.0 でも**グループ ID**（`DailyReportServiceImpl.LINE_GROUP_ID`）へ送っていた。
  トークンは**リポジトリ内に平文で残っている秘密情報**なので、2.0 を止めたあとに
  LINE Developers で再発行し、2.1 の設定には新しい値を入れるのが望ましい
  （再発行すると古いトークンは無効になる）。値をこの文書には書かない。
- 送信に必須なのは 2.0 からある **`LINE_MESSAGING_CHANNEL_ACCESS_TOKEN`**（チャネルアクセストークン）と
  **`LINE_MESSAGING_PUSH_URL`**（既定 `https://api.line.me/v2/bot/message/push`）、送信先ID。
  いずれも「LINE連携」の「Messaging API」グループにある。
- `LINE_MESSAGING_CHANNEL_SECRET` / `LINE_MESSAGING_WEBHOOK_VALIDATE_SIGNATURE` は
  **Webhook（受信）用**なので、送信には使わない（2.1 は受信側が未実装のため、いまは未使用の設定。
  設定画面には 2.0 からそのまま移行した）。
  Channel secret は LINE が webhook に付ける `X-Line-Signature`
  （`Base64(HMAC-SHA256(チャネルシークレット, 本文))`）を検証するための値で、
  2.0 も `LineWebhookServiceImpl#validateSignatureIfNeeded` で同じ計算をしていた。
  2.0 の設定 DB は空だったが、コードにフォールバック値があったため実際はそれを使っていた
  （トークンと同じ扱い。値はこの文書には書かない）。
- 定義の置き場: 画面 `features/system-settings/study2SettingRuntime.ts`（カテゴリ `daily_report`）、
  対応表 `backend/admin-api/.../setting/SettingPageFields.java`（ページ区分 `DAILY_REPORT`）、
  カタログ `database/設定/TBL_COM_設定項目_init.sql`。
  「LINE連携」から移した移行は `database/移行/MIG_COM_設定項目_学習日報LINE通知_20260912.sql`
  （キーは変えずページ区分だけ付け替える）。

## 4. ロール

`/api/user/daily-reports/timetable` が、その生徒の全記録から
**曜日×時限ごとに最も多い教科**を 1 件返す（`appearances`＝その教科だった日数、
`days`＝その枠に記録があった日数）。画面は「3/4」の形で確からしさを示す。
実データ（2026-06-29〜09-10）では 月＝7 限・火〜金＝6 限 で安定しているが、
（曜日,時限）→教科は学期中に変わっているため、断定せずに記録を根拠として見せる。

## 4. 提出の API と検証

| API | 内容 |
|---|---|
| `GET /api/user/daily-reports/status?from=&to=` | 日ごとの 記録あり／提出済／再提出待ち、時限数、掌握度の平均、ノート数、教科、内容入力済の数、**振り返り・今夜の勉強内容**（未展開のマスに出す） |
| `GET /api/user/daily-reports/week?date=` | その週の授業（推定含む）＋日ごとの 提出状態・4 観点・振り返り・宿題 |
| `POST /api/user/daily-reports/lesson` | 1 限ぶんの保存。提出済の日なら `DRAFT` に戻す（メッセージにも「再提出待ちに戻しました」と出す） |
| `POST /api/user/daily-reports/day` | その日の 振り返り・宿題・備考（当日まとめ）を保存する。提出済の日なら `DRAFT` に戻す |
| `POST /api/user/daily-reports/submit` | その日を提出する（記録が無い日・提出済の日は 400） |
| `DELETE /api/user/daily-reports/lesson?date=&period=` | その時限の授業を 1 件消す。**後ろの時限は詰めない**（1 限を消しても 2〜6 限のまま）。提出済の日なら `DRAFT` に戻す |

検証は 4 層で行う。

1. 単体（`DailyReportSubmitTest` 10 件）: 提出の成功・記録なしの拒否・二重提出の拒否・
   保存で下書きに戻ること・status の数え方（提出済と再提出待ちを分ける）・week の日別サマリ
2. 実 DB（`DailyReportRepositoryTest` 12 件）: 移行した 24 件が提出済であること、
   保存 → 提出 → 二重提出 400 → 編集で再提出待ち → 再提出、授業ごとの自己評価とノート理由、
   祝日指定で授業が消えて**「0 限」と出て**提出率の分母から外れること、土日も週に含まれること、
   授業を 1 件消しても時限が詰まらないこと、**提出前は推定の枠が残り、提出すると消えること**、
   **祝日・休日は 0 限のまま提出できること**
3. 画面（`tests/daily-report.spec.ts` 29 件・`daily-report-subjects.spec.ts` 7 件）:
   マスの情報、教科ごとの色、星表示、授業 9 項目のダイアログ
   （時限の選択肢がその日の日報に合わせて変わること・評価を星で選べること）、
   祝日・休日の扱い、展開したマスの中の 3 つのボタン、日曜の幅の切り替え
4. 実機（`tmp/e2e/e2e-daily-report.mjs` 185 件・`tmp/e2e/e2e-daily-report-week.mjs` 18 件）:
   黄→緑→再提出待ちの色の移り変わり、日曜の列の狭さと「日曜の授業があると 7 日とも同じ幅」、
   教科を全部出すこと、**教科ごとの色（副科も色付き・破線）**、授業カードの高さが揃うこと（未提出と提出済で同じ）、
   星表示、**時限の選択肢がその日の記録に合わせて変わること・掌握度と自己評価を星で選べること**、
   ノートのラジオと理由の候補、**未提出の日も「n限 推定」を出してカードの並びが提出済みの日と同じ高さから始まること**、
   **土日も「未提出」と出て 3 つのボタンが押せること**、
   **授業カードのゴミ箱で 1 限だけ消せて時限が詰まらないこと**、
   **提出前は推定の枠が残り、提出すると提出した授業だけになること**、
   **消した時限の枠が残り、下のカードが上に移動しないこと**、
   **幅のある列では 2 つのボタンが 1 行・同じ幅、日曜の細い列では縦並びで文字が切れないこと**、
   祝日にして授業が消えて「0 限」と出て、【提出】も押せること、
   展開したマスの中の【授業追加】【当日まとめ】【提出】まで実ブラウザで通す

## 5. 今回の範囲外

| 一括提出（月まとめ） | 提出は 1 日単位（ユーザーの指定） |
