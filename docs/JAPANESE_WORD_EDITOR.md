# 単語情報管理の修正画面

正式画面の「修正」は、新画面の詳細編集と同じ 11 欄を使用する。基本情報、語義・説明、文型、例文・会話、類義語、使用注意、活用・自他動詞、発音、コロケーション、記憶のヒント、ミニ練習を編集できる。状態と備考も保持する。

編集開始時に `GET /api/user/japanese/words/{wordId}` で最新の情報を取得する。入力はメモリ上の下書きで保持し、学習画面で未保存プレビューを確認できる。キャンセル時は未保存の変更を確認する。デモ専用の AI 操作は正式画面に表示しない。

## 詳細は「版」で持つ

詳細（語義・例文・…）は 1 つの JSON ではなく、**版**（`JPN_単語詳細情報` ＋ 11 の子テーブル）として持つ。

- 有効版は 1 語に 1 つだけ（`状態コード = 'ACTIVE'`。部分 UNIQUE 索引 `uq_jpn_detail_active` が保証する）
- **AI の取得も、画面の編集も、新しい版を作る**。未指定なら最後に作った版（＝最新）が有効
- 版の一覧と切り替えができる（下の API）。誤った編集は古い版に戻せる

### 編集で作られる版と、行の「出所」

保存すると、**今の有効版を複製し、変わった部分だけ入れ替えた新しい版**を作る。行ごとの出所は次の規則で決まる（`JpnWordDetailEditorComposer`）。

| 画面での操作 | 新しい版の行 | 以後の AI 取り直し |
|---|---|---|
| 触っていない（内容が同じ） | 元の出所を引き継ぐ（AI の行は `登録元コード='BATCH'` のまま） | 入れ替えられる |
| 変更した／新しく足した | `登録元コード='APP'`・`手修正フラグ=true` | **消えない**（新しい版へ複製される） |
| 消した | 新しい版に入れない | − |

## 保存 API

`PUT /api/user/japanese/words/{wordId}/editor`

- `word`: 基本情報と編集開始時の `version`。
- `contentVersion`: 詳細の編集開始時の版数。詳細未取得の場合は `0`。**今の有効版の版数と違えば 409**（強制上書きはしない）。
- `detail`: 詳細 JSON。**規範のキー**（`senses` / `examples` / `patterns` / `dialogs` / `synonyms` / `cautions` / `collocations` / `relatedWords` / `usageNotes` / `practices` と語レベルの項目）で送る。サーバーが読むのはこのキーだけ。
  - 旧キー `editorContent` は**サーバーは保存しない**（2.0 形式の画面のための名残。読み出しにも使わない）。

基本情報と詳細は同一トランザクションで保存する。母表と詳細の両方で楽観ロックを検査する。更新者・更新日時を記録し、詳細は `manuallyCorrected: true` とする。DB 操作は既存の MyBatis ログ対象。

成功時は保存済みの `WordDetailResult` を返し、画面の下書きと版数を更新する。失敗・競合時は入力を保持し、競合した版の強制上書きは行わない。読み直す前に必要な入力を控える案内を表示する。

## 版の履歴 API

| API | 内容 |
|---|---|
| `GET /api/user/japanese/words/{wordId}/detail-versions` | 版の一覧（新しい順）。版番号・有効/履歴・AI か人の編集か・AI プロバイダ/モデル・取得日時・各段落の件数 |
| `PUT /api/user/japanese/words/{wordId}/detail-versions/{detailId}/active` | その版を有効にする（body の `version` で楽観ロック。食い違えば 409）。成功すると切り替え後の詳細を返す |

## 同じ表記の別の読み

`alternateReading` は詳細の版ではなく**語の表記から引く**（`JpnWordMapper.findAlternateReading`）。
同じ `見出し語キー` で読みが違う語（読みが未取得のものは除く）があれば、その読みを返す。画面は
「同じ表記に「〜」の読みもあります（別の単語として登録）」と出す。

## 検証

フロントエンドでは既存形式との往復、並べ替え後の再保存、未取得詳細の初回保存、競合時の入力保持・プレビュー・離脱確認、
版の一覧と切り替え（409 のときの案内）を検証する。バックエンドでは**行の出所の判定**（触っていない行＝元の出所、
変更・追加＝`APP`、削除＝入れない）、母表と詳細の版数競合、初回作成の競合、**1 語 1 有効版**を検証する。
実 DB の接続を伴う確認（`STUDY21_DATASOURCE_PASSWORD` を設定した `JapaneseRepositoryTest` と
`JapaneseWordDetailVersionRepositoryTest`）と配備は別途実施する。
