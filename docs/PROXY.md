# プロキシサービス（batS01）

2.0 の **batL01** を 2.1 に移植したもの。名前を **batS01** に変え、実行のきっかけを
「admin-api の起動時に 1 回」と「バッチ管理画面の【再実行】」だけにした
（2.0 が持っていた 6 時間ごと（0/6/12/18 時）の実行は行わない）。

| 項目 | 2.0 | 2.1 |
|---|---|---|
| バッチコード | `batL01`（種別 L） | **`batS01`（種別 S = システム起動時）** |
| 実行のきっかけ | 起動時 ＋ 6 時間ごと ＋ 手動 | **起動時 ＋ 画面の【再実行】** |
| 実装場所 | 2.0 アプリ（`com.study2.proxy`） | **admin-api（`com.study21.admin.proxy`）** |
| DB アクセス | 裸 JDBC（`DataSource`） | **MyBatis Mapper**（`SqlLoggingInterceptor` で記録） |
| ポート | 8888 固定 | `study21.proxy.port`（既定 **7777**。2.0 のプロキシが 8888 を使うため） |

## 1. 何をするか

`ProxyServerService#startIfNeeded()` が、**admin-api と同じ JVM の中に**
LittleProxy（Netty）の HTTP プロキシを起動する（既定 7777 番）。すでに動いていれば何もしない。
2.0 の `BatL01Task` と同じで、「プロキシが起きていることを保証する」のが batS01 の仕事。

- batS01 の業務処理: `backend/admin-api/src/main/java/com/study21/admin/batch/ProxyStartBatchHandler.java`
- 起動フック: `BatchStartupRunner`（`ApplicationReadyEvent` → 種別 S かつ有効なバッチを 1 回実行）
- 履歴には `起動種別='S'`・`依頼元コード='STARTUP'` で残る。画面からの再実行は `起動種別='C'`
- 終了時（`@PreDestroy` / `ContextClosedEvent`）にプロキシを閉じる

## 2. アクセス判定（2.0 と同じ規則）

1. クライアント IP で `NET_端末コントロール情報` を引く
   （`"IPアドレス" = ? AND "状態" = '1'` → `"端末モード"`）。未登録なら拒否。
2. モードごとに許可判定する。

| 端末モード | 表示 | 判定 |
|---|---|---|
| `S` | 停止 | **すべて拒否** |
| `J` | 自由 | **すべて許可**（サイト表を読まない） |
| `G` | ゲーム | **すべて許可**（サイト表を読まない） |
| `T` | 通常 | 許可リストが必要。区分 `STUDY` / `NORMAL` を許可 |
| `K` | 休憩 | 許可リストが必要。区分 `STUDY` / `NORMAL` / `BREAK` を許可 |
| `B` | 勉強 | 許可リストが必要。区分 `STUDY` **のみ**許可 |

3. 許可リストは `NET_サイト情報` の **`承認ステータス='APPROVED'` かつ `状態='1'`** の行。
   判定には `サイトURL` と `ホスト名` だけを使う（2.0 は `サイト名称` も候補にしていたが、
   表示名で許可される事故を防ぐため 2.1 では外した）。
   `判定方法コード`（`PREFIX` / `SUFFIX` / `CONTAINS` / `EXACT`）でリクエストのホストと照合し、
   どれか一致すれば許可する。

判定そのものは `ProxyAccessDecision`（Netty・Spring・DB に依存しない純粋なクラス）に分けてあり、
`ProxyAccessDecisionTest`（16 件）と `ProxyHostMatcherTest`（15 件）で固定している。
拒否の理由は 2.0 と同じ文言で、そのまま画面（403 の応答本文）と通信履歴の `エラー内容` に出る。

| 理由（逐字） |
|---|
| `IPアドレスが取得できないためアクセス不可` |
| `端末情報未登録のためアクセス不可` |
| `停止モードのためアクセス不可` |
| `接続先ホストを識別できないためアクセス不可` |
| `端末ステータスが不正のためアクセス不可`（2.0 と同じく到達しない守衛。未知のモードは「未登録」扱い） |
| `現在モードで許可されたサイトではないためアクセス不可` |
| `アクセス制御情報の取得に失敗したためアクセス不可` |

## 3. 通信履歴

すべてのリクエストを `NET_プロキシ通信履歴情報` に 1 行ずつ記録する（許可も拒否も）。

- 許可: `応答状態コード` は NULL
- 拒否: `応答状態コード=403` と `エラー内容`（理由）を入れる
- `登録元コード='PROXY'`、`登録者/更新者アカウントID` は NULL（プロキシは人が操作しない）
- 2.0 は `受付日時` を空のままにしていたが、2.1 では受付時刻を必ず入れる

DDL は `database/プロキシ/TBL_NET_プロキシ通信履歴情報.sql`、
2.0 の実データの移行は `database/移行/MIG_NET_プロキシ通信履歴_20260912.sql`
（稼働中の 2.0 は batR02 が古い行を消し続けるため、**開始時点の最大 ID を境界にしたスナップショット**を
移行対象にし、件数の検証もそのスナップショットと突き合わせる）。

## 4. 設定・運用

| 項目 | 値 |
|---|---|
| ポート | `study21.proxy.port`（既定 7777。`docker-compose.yml` は `STUDY21_PROXY_PORT`） |
| 起動 | admin-api の起動時（batS01 が有効なとき） |
| 再実行 | バッチ管理画面 →【再実行】（`POST /api/admin/batch/tasks/batS01/rerun`） |
| 有効／無効 | `BAT_バッチコントロール情報`（移行直後は **batS01 だけ有効**） |
| 復旧 | プロキシが落ちたら【再実行】、または admin-api の再起動 |

依存: `org.littleshoot:littleproxy:1.1.2`（2.0 と同じ）。この依存は SLF4J の二重 binding を
持ち込むため、`slf4j-log4j12` と `log4j` を除外している（除外しないと logback が落ちて
`*-app.log` / `*-sql.log` / `*-error.log` が出なくなる）。
