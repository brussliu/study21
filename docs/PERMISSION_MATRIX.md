## 4. 決めていただきたい論点

1. **端末コントロール**を学生に開放するか（2.0 は保護者限定。学生は閲覧のみ／完全に非表示のどちらか）。
2. **バッチ管理 3 画面**を管理者専用にするか、保護者にも見せるか（2.0 は保護者が見られた）。
3. **AI呼出履歴の本文**（プロンプト・レスポンス）を見せる範囲（管理者だけ／保護者も可）。
4. **サイトの承認**を保護者だけにするか（2.0 は保護者のみ。学生は申請だけ）。
5. **保護者の「子どものデータ」の範囲**（複数の子どもがいる場合の切替、子どもの日報の編集可否）。
6. **日本語勉強・リンククリップ・思維導図・設定**に 2.0 の権限表が無いので、同じ仕組みに載せるか。
7. 科目別の先生（2.0 の `teacher_e` / `teacher_m`）を 2.1 でも持つか（持つなら 4 つ目のロール）。
8. 3 エリア（`/admin` `/student` `/parent`）の**メニューを役割ごとに変える**か
   （現状は同じメニューを出している。上の表の「－」はメニューから消す＝実装が必要）。

## 5. 決まったあとの実装方針（案）

- 2.0 と同じ 3 層で持つ: **メニュー表示（A）／画面の操作（B）／API（C）**。
- 保存先は `MST_権限情報` 相当を 2.1 の規約で作り直す（`権限コード` + `ロールコード` + 有効フラグ）。
  2.0 の 53 行はそのまま移行の材料になる。
- 判定は **API（サービス層）で必ず行う**。画面は「押せない・出さない」ための二重化。
- 学生・保護者・管理者の 3 エリアは、ロールごとのメニュー（`resolveMenu(area, role)`）で出し分ける。
- 認証は現在 admin-api が未認証（スケルトン）なので、バッチ管理の権限を効かせるには admin-api の
  認証（admin ログインとのセッション連携）が先に必要（`docs/SECURITY_AND_ROLES.md` の課題）。
