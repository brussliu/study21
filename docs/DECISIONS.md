# 架构决策记录

## 为什么一个 PC 前端

- 管理员、学生、家长在 PC 端共享同一套系统外壳、Design Token 与组件。
- 通过路由区域（`/admin`、`/student`、`/parent`）与 Menu Registry 区分，避免维护多个 PC 应用。

## 为什么一个 Mobile 前端

- 移动端是独立的 Mobile Web / PWA（非 Android 原生 App）。
- 学生与家长主要在移动端使用，共享同一移动外壳与组件。
- 不修改旧 Android 项目（`study2apk`）。

## 为什么两个后端

- 管理员与普通用户（学生/家长）的安全边界、访问频率、发布节奏不同。
- `admin-api` 与 `user-api` 独立运行、独立部署，互不调用。

## 为什么本阶段不做数据库

- 需求明确要求数据库与 DDL 由用户后续独立完成。
- 避免在未确认业务与权限前过早设计表结构。

## 为什么不迁移业务

- 本阶段目标是搭建可构建、可测试的系统骨架。
- 避免在角色权限、DDL 未定的情况下带入业务耦合。

## 尚未决定的问题

- 角色与业务功能的权限映射。
- 数据库表结构 / DDL / 索引 / 外键。
- 认证方案（登录方式、会话、Token）。
- 各功能在 admin-api 还是 user-api 的归属。
- 数据迁移与旧系统切换节奏。
