# 迁移策略（Study 2.0 → Study 2.1）

本阶段**不实际迁移任何业务**。以下为未来按功能迁移的原则与步骤。

## 1. 原则

- 旧系统只读，绝不修改。
- 一次只迁移一个功能。
- 先分析旧页面与 API，再实现新前端与新后端。
- 后续由用户决定角色权限。
- 后续由用户设计 DDL。
- 每个功能独立测试、数据核对、上线、回退。

## 2. 迁移步骤（模板）

1. **分析旧系统**：只读查看旧 JSP 页面、Controller、Service、DDL（如相关）。
2. **设计新功能**：确定 PC 页面、Mobile 页面、admin-api 或 user-api 端点、权限、数据。
3. **实现新前端**：在对应前端应用新增页面与 API 客户端方法。
4. **实现新后端**：在对应后端应用新增 Controller / Service（数据库接入后新增 Repository）。
5. **设计 DDL**：由用户后续独立完成。
6. **测试**：单元测试 + 接口测试 + 手工核对。
7. **数据核对**：与旧系统数据核对。
8. **上线**：灰度 / 切换。
9. **回退**：保留旧系统可回退。
